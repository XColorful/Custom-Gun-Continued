当用户本次任务需要浏览源码时，可以利用项目文档来辅助查找和定位源码位置。

### 路由与匹配逻辑

项目的文档目录结构的设计与代码包目录保持一致。
> 例如`./docs/architecture/core/`对应`core/src/main/java/dev/xcolorful/customgun/core/`，Java包目录为`dev.xcolorful.customgun.core`；则该目录下的文件结构直接对应代码的目录结构

利用文档目录与代码包结构的映射关系，实现代码位置的定位：
- 从`./docs/`开始查阅项目文档
- 将文档文件夹路径对应到 Java 包路径
- core 和 client 模块的架构总览分别位于`./docs/architecture/core/Home.md`和`./docs/architecture/client/Home.md`
- 利用架构总览进行一层目录的快速路由，根据代码类别锁定相关包目录

文档的作用主要在于路由：
- 架构/API文档最深层的文件通常为无内容的占位文件，该设计意图是利用该文档的目录路径来对应到代码的包目录，从而定位并阅读代码中最新的 Javadoc、注释
- 若文档不为空，如某个模块的系统性说明，通常一整个文件夹下都是相关文档

### 逐层与指定文档读取

文档采用逐层读取的方式：
- 列出`./docs/`下的文件和文件夹，根据任务选择相关内容
- 根据当前层阅读到的内容继续跳转到下一层
- 当仍然阅读到路由文档时，继续选择相关内容并向下跳转
- 阅读到具体文档后，将该文档的目录位置作为有效信息，用于辅助定位代码位置

根据用户的提示词决定读取路径：
- 若用户指定了具体文档，则从该目录每一个上层目录中至少阅读一个最可能相关的上层文档，避免遗漏上层路由文档中的信息
- 若用户提及了文档但没指定路径，则通过逐层读取的方式查找该文档；即使未找到，也利用查找过程中定位到的目录辅助确定代码所在包目录

### Wiki文档

一般情况下不需要阅读 Wiki，即`./docs/wiki/`下的内容。

Wiki的路由文档位于`./docs/wiki/Home.md`，阅读方式同样遵循逐层读取。

仅在修改玩家可见内容时主动浏览 Wiki：
- 若本次任务的内容在`Home.md`中找不到路由，则视为 Wiki 中不含相关内容，无需继续查找
- 如果本次任务完成后需要补充相关内容到 Wiki，且用户没有明确说明，先提示并询问用户，否则视为无需修改 Wiki

以下操作需要修改Wiki：
- 修改了Config
- 修改了Command
- 修改了`ResourcePojo`子类的字段Tag名
