    IrisApi api = IrisApi.getInstance();

## 为什么之前颜色会丢

我解压了你放在 Temp-File 的 Complementary Reimagined r5.8.1 直接读它的 program 确认：它**没有单独的粒子 program**，`PARTICLES_TRANSLUCENT` 会落到 `gbuffers_textured.glsl`，而那个 program：

- 顶点着色器里 `normal = normalize(gl_NormalMatrix * gl_Normal)` —— 激光的顶点格式 `POSITION_COLOR_TEX_LIGHTMAP`（Position/Color/UV0/UV2）**没有 Normal 属性** → 法线是垃圾值；
- 片元里按 `textureSize(tex,0) < 1100` 判定「这是粒子」（我们的白 8x8 纹理必然命中），进一堆粒子启发式，并在 `GLOWING_COLORED_PARTICLES` 下给 `emission = 5.0`；
- 然后 `DoLighting(...)` 拿光图给它打光，再走雾和后处理染色。

也就是：颜色被 emission 冲爆 + 亮度完全由光影包的光照/调色决定 —— 和你看到的「跟光影画面同色、看不出绿色」一致。

## 改成什么、为什么

派成 `IrisProgram.BEACON_BEAM`（→ `ShaderKey.BEACON` → Complementary 的 `gbuffers_beaconbeam.glsl`）：

- VS 只读 `gl_MultiTexCoord0` / `gl_Color`，**不需要 Normal**，我们的属性集和 vanilla `BLOCK` 完全一致；
- FS 里 `color *= glColor`（保留设定颜色），并往法线缓冲写 `0.0` → **不进延迟光照**，只叠距离衰减 + 雾 + 后处理，也就是「颜色归我、混合归光影包」；
- 信标光束在 vanilla 本来就能染色，所以光影包必须尊重它的 glColor。

顺带：`assignPipeline` 只写主 pass 表，激光不会进 shadow map。
