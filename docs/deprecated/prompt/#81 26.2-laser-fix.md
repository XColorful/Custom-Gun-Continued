我先核对 1.20.1 的实际写法再回答，尤其是光束是即时绘制还是排队到 bufferSource。

1.20.1 那边的写法确认了。我按它的标记结构把 26.2 分支也对齐。

**是的，1.20.1 不要调换顺序**，我给的三条理由：

1. 1.20.1 的遮挡靠的是「光束先入队 → 换 renderType 时 flush → 镜内遮罩排在后面盖住它」。挪到遮罩之后，遮挡就只剩模板测试一条路可走，把一个已验证正常的机制换成另一个没验证过的。
2. 更要紧的是：1.20.1/26.1.2 在模板窗口内 `getModelBufferSource()` 返回的是**独立即时源**（`GL.stencilBufferSource`），而 `BeamRender` 只 `getBuffer` 不 `endBatch` —— 光束只是排在那份源里，真正绘制时机交给后续 `renderModelPart` 里的 `endBatch()`。挪进窗口等于把绘制时机挂在别人的 flush 上，脆。
3. 26.2 挪位不是为了「顺序」本身，而是为了让 `bakePipelineState` 在**提交那一刻**读到非空的 `CURRENT_STENCIL`；1.20.1 没有这个概念。

所以你现在 1.20.1 的标记方向是对的。26.2 已按它逐字对齐（三处位置：原位 / 接管分支 / `_renderScope` 之后），只是 active 与注释相反，编译通过。

一点补充：**`BeamRender` 那行不需要版本区分**。`RenderTypePipelineBake.bakePipelineState` 在 `[1.20.1, 26.2)` 分支就是 `return base`，所以同一行 `bakePipelineState(getLaserBeam())` 三个版本通用，cherry-pick 时不用拆块。真正需要分版本的只有 `_GunModelRender` 的调用位置。

另外提醒一处你 1.20.1 那版带来的行为变化：`GunModelAR` 接管枪体渲染时，原来（改动前）光束是先画再检查接管的，接管时照样会画；现在两个版本槽都留空，等于接管时不再画光束。我按你的写法在 26.2 也留空了以保持两分支一致 —— 如果这不是有意为之，那段其实不需要版本区分，直接放开调用即可。
