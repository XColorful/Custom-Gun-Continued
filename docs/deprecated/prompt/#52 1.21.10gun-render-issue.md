## 根因

[HumanoidOffhandRender.java:133](app://localhost/epitaxy/core/src/main/java/dev/xcolorful/customgun/client/renderer/shooter/HumanoidOffhandRender.java:133) 用的是 `ItemDisplayContext.GROUND`，而包围显示应该用 `FIXED`。

这个上下文直接决定姿态：`ItemStackRenderState.displayContext` → `SpecialModelRenderer.submit(..., displayContext, ...)` → `NeoBEWLR.submit` → `renderByItem(ctx)` → `GunItemRenderer._applyPositioningTransform`，而那里 `FIXED` 走 `getFixedOriginPath()`、`GROUND` 走 `getGroundOriginPath()` —— 两个不同的定位组，所以整个模型被换了一套姿态（右侧朝上、枪口朝身后、往右倾）。

改动的来源很明确：1.21.10 原版删掉了 `ItemRenderer#renderStatic`（现在 `ItemRenderer` 只剩静态工具方法），移植时被迫手写 `ItemModelResolver` + `ItemStackRenderState#submit`，顺手照搬了 xiao.battleroyale 的 `LootContainerRenderer#renderItems`（那个是渲染地上物品的，用 GROUND 是对的），`FIXED` 那行被注释掉了，还留了句「如果渲染有问题再改」。

旁证：

- 1.20.1 / 1.21.1 / 1.21.4 / 1.21.6 四个分支这句话全是 `renderStatic(..., FIXED, ...)`，1.21.10 起才变成 GROUND —— 和你观察到的分界完全一致。
- 本项目文档 [rendering-entry-points.md:61](app://localhost/epitaxy/docs/architecture/client/render/rendering-entry-points.md:61) 也早就写着这一格是 `FIXED`。

## 改动

只动了一行枚举常量，外加按项目惯例把注释整理成 `// [1.20.1, 1.21.10)` / `// [1.21.10, )` 的版本区间写法，并说明了为什么不能换上下文（避免以后又被改回 GROUND）。
