# 测试数据计算报告（CGC 1.20.1 · b1-a-8：换弹的脏 cube 口径）

**数据**：本目录 3 次独立启动，每个文件 3 段 F12（ak47 / m4a1 裸配 / m4a1 满配 各跑一次自动换弹，0/3/6 秒各触发、10 秒后自动停止）。本批只有 F12，没有 Afterburner。见 [标准.txt](./标准.txt)。
**口径**：均值 ± 1 样本标准差（n=3）。脏 cube 是「脏子树内的 cube 数」，直接对应重烘焙要写的顶点量。
**复现**：`python analyze.py`。

> 本批是 [`b1-a-7`](../b1-a-7/测试数据计算报告.md) 的补充：那一批只有节点口径，本批补上顶点口径，用来验证「节点占比能否代表重烘焙成本」。

## 2. 与节点口径对照

|场景|`Dirty subtree share`（节点）|`Dirty cube share`（顶点）|差|
|---|---:|---:|---:|
|ak47|18.1%|14.8%|−3.3 pp|
|m4a1 裸配|7.7%|7.3%|−0.4 pp|
|m4a1 满配|3.0%|3.3%|+0.3 pp|

**节点口径是可靠的代理**：三把枪的顶点占比与节点占比相差不到 3.3 个百分点，没有出现「cube 密度高导致成本翻倍」的情况。动画驱动的弹匣 / 枪机子树在 cube 密度上略低于模型平均（ak47 最明显），所以按节点估算的残留是偏保守的上界。

## 3. 修正后的残留估算

|场景|遍历（F12）|p99 脏 cube 占比|B1-b 后遍历残留（推算）|
|---|---:|---:|---:|
|ak47 换弹|0.34 ms|44.0%|**≈0.15 ms**|
|m4a1 裸配 换弹|0.55 ms|20.7%|**≈0.11 ms**|
|m4a1 满配 换弹|0.83 ms|9.3%|**≈0.08 ms**|

替换 [`b1-a-7`](../b1-a-7/测试数据计算报告.md) 第 4 节按节点折算的 0.18 / 0.12 / 0.07 ms。满配第一人称的换弹峰值残留约 0.08 ms，占 CGC 2.01 ms 的 4%，B1-b 的目标区间 0.45–0.60 ms 不受影响。

## 4. 说明

- 本批 `Cubes submitted` 与 `Distinct cubes` 略有差异（ak47 469.2 vs 459.5；满配 1760.2 vs 1797.7）：前者是实际提交的 cube（含附加弹匣直发的几何），后者是按节点树统计的 cube（含被替换渲染的节点）。分母用 `Distinct cubes`，两者差 1%–2%，不影响结论。
- `Dirty cube share` 的均值（14.8% / 7.3% / 3.3%）同样被空闲帧稀释，**评估用 p99**。
- 本批没有 AF，帧时间只用于与 `b1-a-7` 交叉核对（1.67 / 1.86 / 3.12 vs 1.62 / 1.84 / 3.08），在噪声内一致。
