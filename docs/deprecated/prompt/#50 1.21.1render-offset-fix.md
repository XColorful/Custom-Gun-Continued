## 根因：1.21.1 起手部 poseStack 的基底换了坐标系，而 `cacheMuzzlePosition` 的 FOV 补偿仍按旧坐标系写

[GunItemRenderer.java:306](app://localhost/epitaxy/core/src/main/java/dev/xcolorful/customgun/client/renderer/item/GunItemRenderer.java:306) 采集枪口偏移：

```java
State.muzzleRenderOffset.set(pose.m30(), pose.m31(),
        pose.m32() * tan(itemRenderFov/2) / tan(levelRenderFov/2));
```

- **1.20.1–1.20.4**：手部 poseStack 基底是恒等，view 旋转只在外层 modelview 里 → `m30/m31/m32` 是**摄像机（view）坐标系**，`m32` 正好就是「沿视线」分量，缩放它是对的。
- **1.21.1 起**：`GameRenderer.renderItemInHand` 给手部栈基底加了 `camera.rotation().conjugate()` 的逆 → 采到的偏移变成**世界轴**向量。`m32` 成了世界 z，只在 yaw=0/180 时与视线共线，yaw=±90 时完全垂直。

于是把世界 z 分量单独拉长、`m30/m31` 不动 → 向量方向被拽偏，横向上多出一个偏移量：

```
横向分量 = -(fovRatio - 1) · L · sin(2·yaw) · cos(pitch) / 2
```

**这解释了你实测的全部 8 个朝向**：yaw=0/±90/180 时 sin(2yaw)=0 → 不偏；±45/±135 时取极值，且 45/-135 往左、-45/135 往右（与 `fovRatio` 的符号一起推出正负，开镜时 fovRatio>1，方向与你观察到的完全一致）；pitch 只以 `cos(pitch)` 进入，所以看着「不影响」。幅度正比于 `fovRatio - 1` → **腰射时两手部/世界 FOV 一致，几乎看不出；开镜才明显** ✓。曳光弹起点就是从这个偏移来的，所以跟着一起偏 ✓。

## 改动（1 个文件，+30/−8）

[cacheMuzzlePosition](app://localhost/epitaxy/core/src/main/java/dev/xcolorful/customgun/client/renderer/item/GunItemRenderer.java:306)：改为**沿摄像机视线方向投影得到「深度」分量，只缩放它**，横向分量保持不动（这正是原代码在 view 坐标系下的语义）。视线方向用 `camera.getYRot()/getXRot()` 按标准 MC 约定现算（世界向量，与摄像机四元数约定无关）。1.20.x 的写法按项目惯例注释保留在文件里。

## 根因（枪模型）：动画约束变换在把补偿量按「世界轴」施加

[GunRendererAddon._applyAnimationConstraintTransform](app://localhost/epitaxy/core/src/main/java/dev/xcolorful/customgun/client/renderer/item/gun/GunRendererAddon.java:371)（= 上游 TACZ `FirstPersonRenderGunEvent` 里同名的那段）原本是：

```java
inverseTranslation.mulDirection(poseStack.last().pose());          // 按 pose 矩阵的父坐标系
inverseTranslation.mul(translationICA.x()-1, translationICA.y()-1, 1-translationICA.z());
...
poseMatrix.m30(m30 - x*weight); m31(m31 - y*weight); m32(m32 + z*weight);
```

- **1.20.x**：手部 poseStack 的父坐标系 = 摄像机（view）坐标系，而 view 坐标系 ≈ 枪自身姿态（开镜时枪管就对准视线）→ 系数按它施加基本是对的，所以看起来正常。
- **1.21.1 起**：基底换成了 `inv(摄像机旋转)`，父坐标系变成**世界坐标系** → 同一套系数被按世界轴施加，补偿量就随 yaw 变了：

```
横向偏移 ∝ -sin(2·yaw) · cos(pitch)
```

yaw=0/±90/180 时为零、±45/±135 时正负最大，pitch 只以 `cos(pitch)` 进入 —— 和你的实测完全一致；而 `weight = 瞄准进度 × (1-改装界面进度)`，**与瞄具无关**，所以「没装倍镜也偏、腰射不偏」也对上了 ✓。它改的是整把枪的 pose，枪口偏移（曳光弹起点）是被一起带走的，所以两个症状同源。
