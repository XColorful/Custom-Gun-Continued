# 测试数据计算报告（CGC 1.20.1 · 26.35.11.1-6 / b1-c-b：B1-c-B 光照原地改写）

**数据**：`b1-c-b/` 下 4 次独立启动（n=4），每次含 Afterburner 与 F12 两段，时间不重叠；测试流程见 [`b1-c-b/标准.txt`](./b1-c-b/标准.txt)，与 `26.35.11.1-5/b1-b-3` 相同。
- `cgc1 (N).txt`：Afterburner 7 步 = 空手（夜晚静止）/ ak47 移动 / ak47+光影 静止 / ak47+光影 移动 / 满配 移动 / 满配+光影 静止 / 满配+光影 移动
- `cgc1-builtin (N).txt`：F12 4 段 = ak47 移动 / ak47+光影 移动 / 满配 移动 / 满配+光影 移动
- 本批没有新增探针；判据是 `Bake rebuilds` 与 Afterburner 的 1% / 0.1% low。

**改动**：B1-c-B（见 [光照解耦](../../refactor/lighting-decoupling.md)）——第一人称分块网格不再按光照建键，烘焙后留一份 CPU 副本，光照变化时原地改写 uv2 并重传原 VBO；每个键保留主 / 阴影 2 份光照变体。
**场景**：夜晚、脚下火把、按 W 走 8 格后传送回起点、再走 16 格；移动时每跨一格方块光 −1。
**口径**：帧时间 = 1000 / FPS；均值 ± 1 样本标准差。`Static bake` 是**命中帧内所有烘焙之和**，不是单次烘焙；单次光照变化字节 = 每帧平均字节 ÷ 命中帧比例。手动起停误差 ≤0.5–1 s。
**复现**：`python analyze.py`。

## 3. 剩余重建的定位（只出现在满配+光影）

|项|满配+光影（本批）|满配+光影（b1-b-3）|
|---|---:|---:|
|`Static bake`（命中帧合计）|5.327 ± 0.963|9.341|
|`Bake emit`|**4.916 ± 0.931**|8.788|
|`Bake buffer create`|0.055 ± 0.010|0.049|
|`Bake upload`|0.340 ± 0.047|0.496|
|emit 占剩余成本|92.3%|—|

- 剩余成本的 **92% 仍是顶点发射**，上传只占 6.4%。所以「再做方案 A（独立 uv2 流）」消不掉这部分——A 省的正是上传。
- 触发频率只有 1.16 次/秒（旧 2.9 次/秒），每次重建约一半几何（8.8 块 × 105 KB）。
- 只有「满配 + 光影」有残留：`ak47+光影`、`满配`、`ak47` 三段都是 0，说明它不是「光影下光照变化」这一条路径的普遍行为。
- **原因未定位**。现有探针只能看到「重建发生了」，区分不了下面两类，需要一次针对性采集：
  1. **变体填充**：每个（块 × `RenderType`）的两份光照变体只有在遇到新光照时才建，第一次跨亮度边界仍要烘焙一次。与「第二次走同一段路变平」吻合，但 F12 窗口按标准也是第二次走，仍有 118 次重建，单纯的「一次填满」解释不了。
  2. **回退重建**：`BakedMesh.updateLight` 返回 false 的分支（烘焙时恰好满亮、取不到 VBO id）会退回重新烘焙。这一类会在每次光照变化时复现，与「第二次走变平」矛盾。
- 判定方法：在 `updateLight` 的两个 false 分支各加一个临时计数器，跑一次移动段即可区分；按本批约定没有随改动加入。

## 4. 与方案 A 的对比

- A 只在「上传」上更省：满配+光影一次光照变化 1733.8 KB → 约 133 KB（4 B/顶点），按本批实测的上传速率折算 ≈0.04 ms，比 B 每次再省 ≈0.3–0.45 ms；按旧频率 2.9 次/秒计约 **0.1% 平均帧时间**。
- 本批 B 的实测收益：每次事件 9.246 → 5.327 ms，重建字节 −79%，1% low +72%。两者不在一个量级，且剩余成本的 92% 是 emit，A 不改变它。
- 因此 A 的定位不变：后续降低上传 / 显存 / 缓存键的优化，不是本阶段掉帧的解法。

## 5. 实机观察对照

- 观察：m4（满配）光影下仍有周期性 low，幅度与上一批 ak47 光影的 low 波动相当、比上一批满配光影小；同一段路第二次走时帧率曲线非常平。
- 数据吻合的部分：单次成本 9.2 → 5.3 ms（约减半）、频率 2.9 → 1.16 次/秒，所以「仍有、但更小更稀」；6.87 ms 的帧塞不下 5.3 ms 的重建，p99 仍在 11.6 ms，所以肉眼仍可见。ak47 光影现在是 0 次重建（旧 2.8 次/秒、单次 2.7 ms），对应「只剩偶发小波动」。
- 不吻合的部分：F12 窗口本身就是第二次走，却仍有 1.16 次/秒的重建，说明「第二次走变平」不能完全由现有解释覆盖，见第 3 节的未定位项。

## 6. 结论

1. **B1-c-B 按预期消掉了大部分光照尖峰**：无光影与 ak47+光影的重建次数归零；满配+光影重建字节 −79%，单次成本 −42%，1% low 59.1 → 101.8、0.1% low 41.1 → 58.5。
2. **未完全达标**：满配+光影移动的 1% low 仍低于同场景静止（101.8 vs 132.6），仍有 ~1.2 次/秒的整段重传，原因未定位（第 3 节）。
3. **整模静态路径仍按光照建键**（展示框 / 地面 / 第三人称，同一份网格被多个实例共享），本次未覆盖，留给 B2。
4. 方案 A 的额外收益约 0.1% 平均帧时间，且消除不了剩余尖峰（92% 是 emit）；维持「A 作为后续上传优化」的定位。
