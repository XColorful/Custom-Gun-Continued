## 覆盖范围与门槛

|条件|说明|
|---|---|
|`ItemDisplayContext.FIXED`|物品展示框。掉落物（`GROUND`）会旋转 / 浮动、第三人称的姿势每帧变化，都不合批，继续走 B1 的每实例矩阵绘制|
|无光影包|光影包的影子 pass 会再渲染一遍实体，而帧末 flush 拿不到影子 pass 自己的相机矩阵；切光影时整批作废，退回 B1|
|`renderType` 为 `NEW_ENTITY` + `QUADS`|否则该实例退回 B1（`BakedMesh` 自己会处理扩展格式）|
|`StaticBake.ENABLED` 且非 `FORCE_REBUILD`|`FORCE_REBUILD` 下仍走逐实例重烘，保持原有验收语义|
|同一实体、同一 RenderType 的几何稳定|世界矩阵或内容每帧都变（第三方把 FIXED 用在动画上）的实例，重建 5 次后永久退回 B1|

**光影下暂不合批的依据**：B1-a 之后开光影的 multi 是 7.193 ms，同场景 9 个空展示框基线 6.68 ms（[`26.35.11.1-4`](../benchmark/26.35.11.1-4/测试数据计算报告.md)），
CGC 只剩约 0.5 ms 且已经贴近 GPU 下限，合批的 draw 收益没有可见空间；同时光影的影子 pass 会再渲染一遍实体，
帧末 flush 拿不到影子 pass 自己的相机矩阵。因此 B2 只在无光影下启用，光影包下完全退回 B1。

## 批次怎么组织

- **实例身份** = `(实体 id, RenderType, 模型对象, 子网格)`；实体 id 由 `EntityRenderDispatcherMixin` 在 `EntityRenderDispatcher#render` 前后登记，
  `renderByItem` 自己拿不到实体。
- **世界矩阵**：姿态是「世界 → 视图」，从里面剥掉相机得到世界矩阵
  `W = T(camPos) * R_cam^-1 * pose`；`R_cam^-1` 取 `RenderSystem.getInverseViewRotationMatrix()`（`GameRenderer` 在进入世界渲染前按同一份姿态算出）。
  相机平移用 double 参与组装，`pose` 的平移本身已经是相机相对量，精度不受世界坐标大小影响。
- **锚点**：每个 `RenderType` 一个批次，锚点取批次第一份几何世界坐标的 `floor`。顶点按「锚点相对坐标」存放，绘制矩阵为
  `R_cam * T(anchor - camPos)`。镜头移动不会让网格失效；锚点只在批次清空后重建时才重新选取。
- **顶点**：`BakedMesh#emitGeometry` 只发射顶点（复用同一个 `BufferBuilder` 池），`StaticBatch` 把位置用 `W`、法线用 `invT(L_W)` 变换到锚点坐标系。
  法线与 B1 逐位一致：着色器仍用 `invT(mat3(ModelViewMat))`，而 `invT(R_cam) * invT(L_W) = invT(R_cam * L_W)`。
- **拼接**：`BufferBuilder#putBulkData` 逐实例追加顶点字节，`end()` 由原版生成连续索引，一次 `VertexBuffer.upload`。
  索引走原版的 sequential index buffer，不需要自己维护 IBO。
- **绘制**：每个 `RenderType` 一次 `setupRenderState` + 一次 `drawWithShader`，全场景从「每枪 9 次」降到「不同 RenderType 数」（实测上限 6）。

## 失效与生命周期

|触发|处置|
|---|---|
|实例首次出现|发射顶点并加入批次，整个批次重排上传|
|内容变化（指纹 / overlay / 颜色）|替换该实例的顶点块，批次重排|
|世界矩阵变化（量化到 1/16 格 + 旋转 1e-3）|同上；频繁变化的实例退回 B1|
|光照变化|**只改写该实例的 uv2 区间并 `glBufferSubData` 这一段**，不重建批次|
|展示框里的物品被换掉 / 清空|不会再提交，靠记录的物品识别并丢弃该实例|
|实体卸载 / 超出原版实体渲染距离（64 格）|丢弃该实例|
|镜头移出视锥|**保留**该实例并照常绘制：世界位置正确，镜头平移不会反复重建；重新进入视锥时按新光照改写|
|切换维度 / 光影包 / 资源重载|全部作废（`StaticBakeCache#clearAll` 一并调用）|
|上限|128 个实例 / 32 MiB，超出淘汰最久未出现的实例|

## 收益边界

组键是 `RenderType`（纹理 + 渲染状态），**不是「同一把枪」**；枪体纹理按枪唯一，所以：

|场景（9 个展示框）|B1 展示 draw|B2 展示 draw|节省|
|---|---:|---:|---:|
|9 把同款 ak47|9|1|8 次 ≈ 0.06 ms|
|9 把同款满配|72|24（6 合批 + 18 镜身）|48 次 ≈ 0.37 ms|
|9 把不同裸枪|9|9|**0**|
|9 把不同满配、共用配件与瞄具|72|32|40 次 ≈ 0.31 ms|
|9 把不同满配、配件各异|72|~72|**0**|

- **不同枪的枪体永远不合并**；只有同款重复展示、或不同枪共用同一配件 / 瞄具纹理时才有收益。
- 同款**裸枪**的收益只有 8 次 draw（≈0.06 ms），本批 ak47 组的帧时间优势主要不是 B2。
- `26.35.11.1-7` 的 −19.6% 是「同款满配」的最好情况，不能外推到混合展示；裸枪收藏墙为 0。
- 瞄具镜身（每枪 2 次）走 `drawOrBakePatchable`、未合批；并入批次可再省 ≈18 次 draw（≈0.14 ms），但涉及绘制顺序与模板语义，未做。
- 状态段（functional 回调、可见性、指纹）仍是「每实例 × 每帧」，不受 B2 影响。

实测、场景矩阵与固定收益图见[报告](../benchmark/26.35.11.1-7/测试数据计算报告.md)第 8、9 节。

## 合批范围（问答）

- **不是「同一把枪才合并」**：合批键是 `RenderType`（纹理 + 渲染状态），实例键是 `(实体, RenderType, 模型对象, 子网格)`。同款枪天然共享一个 `RenderType`；不同枪只要纹理与状态相同也会进同一批，不同纹理则各成一批。**draw 数 = 同场景不同 RenderType 数**，与枪数无关。
- **单个实例也走合批**：只有一份几何时就是「1 块、1 次 draw」，不会被排除；合批的收益在实例数增加时才体现。
- **GROUND 不合批，即使当前没有旋转**：`batching()` 只接受 `ItemDisplayContext.FIXED`。掉落物的位姿由实体动画驱动（旋转 / 浮动），实现里不做「这一帧是否在变」的额外判断，直接排除。要覆盖它必须改成「位姿在容差内不变才加入、变化时移出」，而掉落物常见多份副本、收益有限。
- **玩家手持不合批**：第一人称走 B1-b 分块烘焙；第三人称是 `THIRD_PERSON_*`，走 B1 的每实例矩阵。两者都不进入 B2。
- **不会取消手持枪的渲染**：非 `FIXED` 上下文 `batching()` 返回 false，`renderBaked` 原样落到原有路径；`FIXED` 下 `submit()` 失败也会落回逐实例绘制。被合批的展示实例只是**延后**到实体循环结束后统一绘制，不会丢失。`flush()` 挂在 `LevelRenderer.renderLevel` 的实体循环之后，正常帧必然执行。

## 模板窗口

展示框与掉落物 / 第三人称**不再开启模板测试**（`_GunModelRender#_renderScope` 只在第一人称开启）。
静态展示本来就不写模板值，开启测试只会读到上一处残留；合批后枪体已延后到帧末，旧的「窗口内绘制」顺序不再成立。
第一人称的模板窗口与准心路径完全未改动。

> **这一项已从 B2 中拆出独立保留**（2026-11-14）：非第一人称不再进入瞄具模板流程（不开测试、不设模板操作、不逐实例关闭测试、不清模板缓冲），**无条件生效、无开关**。
> 它与合批正交，收益与行为变化见[方案](./Home.md)「静态展示的模板测试」与[报告](../benchmark/26.35.11.1-7/测试数据计算报告.md)第 8 节。

## 新增探针

|名称|类型|含义|
|---|---|---|
|`Batch build` / `Batch rebuilds`|计时 / 计数|一次批次拼接 + 整段上传；稳态应为 0（批只在实例集合或内容变化时重建）|
|`Batch candidates` / `Batch submits`|计数|通过 `batching()` 与登记（新建或命中）成功的实例数；两者应相等|
|`Batch draws`|计数|每帧由合批发出的 draw 次数（应等于同场景的 RenderType 数）|
|`Batch: guard/emit reject`、`Batch: content rebake`、`Batch: unbatched`|计数|被守卫拒绝 / 发射失败 / 内容变化重发 / 暂缓合批的实例数，用于定位「没有合并」|
|`[B2] FIXED submit: …` / `[B2] emit rejected: …` / `[B2] batch block baked: …`|日志|首次各输出一次，给出判定依据与实际步长 / 顶点数|
|`Light patches` / `Light patch bytes`|计数|沿用 B1-c-B，合批后度量的是「实例区间」而不是整份网格|

## 验收清单（人工）

1. **画面**：9 个展示框（裸配 / 满配）与 `StaticBatch.ENABLED = false` 时逐像素级一致；枪体、配件、瞄具镜身与目镜环位置正确。
2. **光照**：展示框分布在不同亮度处，枪体亮度各自正确；逐格移动时枪体亮度跟随，且 F12 下 `Batch rebuilds` 移动段为 0、`Light patches` > 0。
3. **失效**：改装界面换配件、换弹匣类别、装 / 卸瞄具后，展示框内容立即更新；把展示框里的物品换成别的物品 / 清空，枪立即消失。
4. **镜头**：左右平移、转身不应出现 `Batch rebuilds` 尖峰（只有进出视锥不重建）；远距离（>64 格）不绘制。
5. **光影**：开光影包后应完全走 B1 路径（`Batch rebuilds = 0`、无 `Batch build`），画面与关闭时一致。
6. **探针**：F12 后 `Draw calls` 从 81 降到个位数；`Distinct RenderTypes` 不再随枪数增长。

## 已知风险

- **相机矩阵来源**：批次完全依赖 `RenderSystem.getInverseViewRotationMatrix()` 与世界矩阵剥离的等价性（已用 JOML 离线核对：
  位置误差 ~3e-5 格、法线 ~1e-7）。1.20.1 之外版本的对应值需要重新确认。
- **非 `ItemFrame` 的 FIXED 实例**：只按「实体存在 + 在渲染距离内」保活，没有内容识别；这类实例若内容变化且不在视锥内，会保留到下次进入视锥。
- **组合变化时的整段重传**：实例增删会重排并整段上传（9 把满配约 8 MB）。镜头平移不会触发；只有物品被换 / 实体卸载 / 进入 64 格范围时发生。
- **展示框不再做模板测试**：这是有意的语义修正，见上文「模板窗口」。
