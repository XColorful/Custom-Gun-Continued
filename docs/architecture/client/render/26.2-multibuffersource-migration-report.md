# 26.2 MultiBufferSource 移除移植调查报告

> 项目: Custom Gun Continued
> 移植目标: 26.1.2 → 26.2 NeoForge
> 涉及范围: `MultiBufferSource` 移除带来的渲染提交方式变更
> 日期: 2026-08-14

---

## 一、概述

Minecraft 26.2 对渲染管线做了根本性重构，**移除了 `MultiBufferSource` 类**。在 26.1.2 及更早版本中，自定义渲染采用「即时模式 (Immediate Mode)」：通过 `mc.renderBuffers().bufferSource()` 获取全局 `MultiBufferSource.BufferSource`，调用 `bufferSource.getBuffer(renderType)` 拿到 `VertexConsumer` 写入顶点，最后 `bufferSource.endBatch()` 提交到 GPU。

26.2 全面转向**延迟提交节点 (Submit Node) 系统**：`MultiBufferSource` 与 `endBatch` 机制被彻底移除，所有自定义几何必须通过 `SubmitNodeCollector` 接口提交。CGC 中存在 19 个包含 `MultiBufferSource` import 的源文件，这些是必须修改的场景。本报告梳理 CGC 对 `MultiBufferSource` 的各类使用、原版 26.2 的变更，以及已完成的移植方案。

---

## 二、CGC 对 MultiBufferSource 的使用分类

按使用场景可分为以下几类：

| 类别 | 文件 | 旧用法 (26.1.2) |
|------|------|----------------|
| 基岩版模型渲染 | `ModelObject.java`、`_AttachmentModelRender.java` | `mc.renderBuffers().bufferSource()` + `getBuffer(renderType)` + `endBatch()` |
| 功能性渲染器 | `BeamRender.java`、`MuzzleFlashRender.java`、`AttachmentRender.java` | 同上 |
| 文字渲染 | `TextRender.java` | `font.drawInBatch(..., bufferSource, ...)` + `endBatch()` |
| 第一人称手臂 | `ClientRenderHelper.java`、`HandRender.java`、`FirstPersonRender.java` | `renderBuffers().bufferSource()` + `endBatch()` |
| BEWLR 物品渲染接口 | `IBlockEntityWithoutLevelRenderer.java`、`BlockEntityWithoutLevelRenderer.java`、`GunItemRenderer.java`、`AnimateGeoItemRenderer.java`、`AttachmentItemRenderer.java`、`AmmoItemRenderer.java` | 方法签名中的 `MultiBufferSource buffer` 参数 + `buffer.getBuffer(...)` |
| 实体渲染 | `GunProjectileRenderer.java` | `submit()` 中调用 `renderBuffers().bufferSource()` |
| Oculus 兼容 | `OculusCompat.java` | `endBatch(MultiBufferSource.BufferSource)` 注入点 |
| 手部渲染事件接口 | `IRenderHandEvent.java`、`NeoRenderHandEvent.java`、`ForgeRenderHandEvent.java` | `getMultiBufferSource()` 抽象方法 |
| 未使用 import | `IAnimateGeoItemRendererOperator.java` | 仅 import，未使用 |

其中 `ForgeRenderHandEvent.java` 属于 `forge-compat` 模块，该模块不在本分支 (`26.2neoforge`) 的构建范围内（`settings.gradle` 仅 `include("core", "neoforge-compat")`），故未作修改。

## 三、原版 26.2 的变更

### 3.1 `MultiBufferSource` 类被移除

- `mc.renderBuffers().bufferSource()` 不再存在。`RenderBuffers` 仍存在，但只提供 `fixedBufferPack()`、`sectionBufferPool()`、`stagedVertexBuffer()`，不提供 `bufferSource()`。
- `MultiBufferSource.BufferSource.endBatch()` 机制随之消失。

### 3.2 `SubmitNodeCollector` 取代缓冲区源

关键 API（`net.minecraft.client.renderer`）：

```java
public interface SubmitNodeCollector extends OrderedSubmitNodeCollector {
    interface CustomGeometryRenderer {
        void render(PoseStack.Pose pose, VertexConsumer buffer);
    }
}

// OrderedSubmitNodeCollector 中的关键方法
void submitCustomGeometry(PoseStack poseStack, RenderType renderType, CustomGeometryRenderer renderer);
void submitText(PoseStack poseStack, float x, float y, FormattedCharSequence string,
                boolean dropShadow, Font.DisplayMode displayMode, int lightCoords,
                int color, int backgroundColor, int outlineColor);
```

- `submitCustomGeometry` 在提交时对 `poseStack.last()` 做快照，`CustomGeometryRenderer.render(pose, buffer)` 在渲染阶段才被回调，`pose` 是快照，`buffer` 是目标 `VertexConsumer`。
- `Font.drawInBatch(...)` 被移除，文字渲染改由 `submitText(...)` 提交。

### 3.3 其他 26.2 渲染 API 变更（本任务中一并修复）

- `RenderPipelines.MATRICES_PROJECTION_SNIPPET` 移除 → 用 `RenderPipelines.MATRICES_FOG_SNIPPET`（等价于 `GLOBALS + MATRICES_PROJECTION + FOG`）替代。
- `RenderPipeline.Builder.withVertexFormat(format, mode)` / `.withSampler(name)` 移除 → `.withVertexBinding(0, format)` + `.withPrimitiveTopology(PrimitiveTopology.QUADS)` + `.withBindGroupLayout(BindGroupLayouts.XXX)`。
- `VertexFormat.Mode` 移除 → `com.mojang.blaze3d.PrimitiveTopology`。
- `Tesselator.getInstance().begin(mode, format)` 移除 → `new BufferBuilder(new ByteBufferBuilder(n), PrimitiveTopology.XXX, DefaultVertexFormat.XXX)`。
- `RenderType.draw(MeshData)` 移除。
- `Minecraft.getInstance().getMainRenderTarget()` → `gameRenderer.mainRenderTarget()`。
- `gameRenderer.getMainCamera()` → `gameRenderer.mainCamera()`。
- `ViewportEvent.ComputeFov.usedConfiguredFov()` 移除 → `IComputeFovEvent.useConfiguredFov()` 改为 `@Deprecated` 默认返回 `null`。

## 四、移植方案

### 4.1 核心模式：`MultiBufferSource` → `SubmitNodeCollector.submitCustomGeometry`

所有原先「拉取 buffer 写顶点 → endBatch」的代码，统一改为：

```java
SubmitNodeCollector collector = ClientRenderHelper.FirstPersonArmHelper.getFirstPersonArmCollector();
if (collector == null) return;
collector.submitCustomGeometry(poseStack, renderType, (pose, builder) -> {
    PoseStack ps = new PoseStack();
    ps.last().set(pose);              // 从快照重建 PoseStack，避免污染调用方
    part.render(ps, transformType, builder, light, overlay);
});
```

### 4.2 收集器传递方式

`ModelObject.render()` 等深层渲染方法无法直接拿到 `SubmitNodeCollector`，故沿用既有的 `ClientRenderHelper.FirstPersonArmHelper` 线程局部变量 (`ThreadLocal<SubmitNodeCollector>`) 作为「当前渲染收集器」，在各渲染入口设置、内部读取：

- 入口设置：`GunItemRenderer.renderFirstPerson` / `AnimateGeoItemRenderer.renderFirstPerson`（取自 `IRenderHandEvent.getMultiBufferSource_SubmitNodeCollector()`）、各 `renderByItem`（取自签名参数）、`GunProjectileRenderer.submit`（取自 `submitNodeCollector` 参数）。
- 内部读取：`ModelObject.render`、`BeamRender`、`MuzzleFlashRender`、`AttachmentRender`、`TextRender`、`_AttachmentModelRender` 等。
- 为 `FirstPersonArmHelper` 增加了 `getFirstPersonArmCollector()` 读取方法。

### 4.3 各场景具体改动

- **模型渲染** (`ModelObject.render`)：主几何体与 `delegateRenderers` 委托渲染统一放入 `submitCustomGeometry` 的 lambda 中；`OculusCompat.endBatch` / `bufferSource.endBatch()` 删除。
- **功能性渲染器** (`BeamRender` / `MuzzleFlashRender` / `AttachmentRender` / `_AttachmentModelRender.renderModelPart`)：`getBuffer(renderType)` + `endBatch` 改为 `submitCustomGeometry`。
- **文字渲染** (`TextRender`)：`font.drawInBatch(...)` + `endBatch` 改为 `collector.submitText(poseStack, x, y, Component.literal(text).getVisualOrderText(), shadow, DisplayMode.NORMAL, packLight, color, 0, 0)`。
- **手臂渲染** (`ClientRenderHelper.renderFirstPersonArm` / `HandRender` / `FirstPersonRender`)：删除无效的 `buffer` 变量与 `endBatch()`，手臂经由 `AvatarRenderer.renderRightHand/renderLeftHand(..., collector, ...)` 直接提交。
- **BEWLR 接口** (`IBlockEntityWithoutLevelRenderer` 及实现类)：`renderByItem` 签名中的 `MultiBufferSource` 改为 `SubmitNodeCollector`；槽位贴图 (`SlotModel.renderToBuffer`) 改用 `submitCustomGeometry`；模型渲染前设置收集器。
- **实体渲染** (`GunProjectileRenderer`)：`submit()` 直接传入 `submitNodeCollector`，`render`/`_renderAmmoObject`/`_renderTracer` 的 `MultiBufferSource` 参数改为 `SubmitNodeCollector`。
- **Oculus 兼容** (`OculusCompat`)：`endBatch(MultiBufferSource.BufferSource)` 方法及其调用点全部删除（26.2 无等效机制）。
- **事件接口** (`IRenderHandEvent`)：删除 `@Deprecated getMultiBufferSource()`，保留 `getMultiBufferSource_SubmitNodeCollector()`。

## 六、已知的运行时风险

本移植以「通过编译」为首要目标，以下点仍需运行时验证（与 BattleRoyale 26.2 移植时的情况类似，均需进游戏测试）：

1. **委托渲染 (delegateRenderers) 的提交时序**：`ModelObject.render` 将委托渲染器放在 `submitCustomGeometry` 的 lambda 内处理，其内部再调用 `collector.submitXxx` 属于嵌套提交。若提交列表在渲染阶段不支持追加，枪口火焰、文字、抛壳、手臂等「延迟渲染」效果可能出现顺序或缺失问题。
2. **`_AttachmentModelRender.renderModelPart` 的 `visible` 标志**：原「`visible=true` → 渲染 → `visible=false`」改为在 lambda 内设置，语义已尽量保持，但需验证瞄准镜模板缓冲 (stencil) 渲染。
3. **`renderOcularAndDivision` 的圆形模板层**：原先用 `Tesselator` + `TRIANGLE_FAN` + `RenderType.draw`，现改为 `submitCustomGeometry`（拓扑/顶点格式由传入的 `renderType` 决定），圆形瞄准镜遮罩需验证。
4. **`ClientRenderRegistry.LaserBeamRenderState`**：该自定义 pipeline 本为死代码（`getLaserBeam()` 实际返回 `RenderTypes.entityTranslucent`），仅做了编译层面的适配。

# English

# 26.2 MultiBufferSource Removal Migration Report

> Project: Custom Gun Continued
> Target: 26.1.2 → 26.2 NeoForge
> Scope: rendering submission changes caused by `MultiBufferSource` removal

## 1. Overview

Minecraft 26.2 fundamentally reworked the rendering pipeline and **removed the `MultiBufferSource` class**. Pre-26.2 custom rendering used the "immediate mode": `mc.renderBuffers().bufferSource()` → `getBuffer(renderType)` → write vertices → `endBatch()`. 26.2 replaces this with a **deferred submit-node system**: all custom geometry must be submitted through `SubmitNodeCollector`. This report surveys CGC's `MultiBufferSource` usages, the vanilla 26.2 changes, and the migration that was applied.

## 2. CGC `MultiBufferSource` Usage Categories

| Category | Files |
|----------|-------|
| Bedrock model rendering | `ModelObject`, `_AttachmentModelRender` |
| Functional renderers | `BeamRender`, `MuzzleFlashRender`, `AttachmentRender` |
| Text rendering | `TextRender` |
| First-person arm | `ClientRenderHelper`, `HandRender`, `FirstPersonRender` |
| BEWLR item render API | `IBlockEntityWithoutLevelRenderer`, `BlockEntityWithoutLevelRenderer`, `GunItemRenderer`, `AnimateGeoItemRenderer`, `AttachmentItemRenderer`, `AmmoItemRenderer` |
| Entity rendering | `GunProjectileRenderer` |
| Oculus compat | `OculusCompat` |
| Hand event API | `IRenderHandEvent`, `NeoRenderHandEvent`, `ForgeRenderHandEvent` |
| Unused import | `IAnimateGeoItemRendererOperator` |

`forge-compat` is not built on this branch (`settings.gradle` only includes `core` and `neoforge-compat`), so it was left untouched.

## 3. Vanilla 26.2 Changes

- `MultiBufferSource` removed; `RenderBuffers.bufferSource()` gone.
- `SubmitNodeCollector.submitCustomGeometry(PoseStack, RenderType, CustomGeometryRenderer)` where `CustomGeometryRenderer.render(PoseStack.Pose pose, VertexConsumer buffer)`.
- `SubmitNodeCollector.submitText(...)` replaces `Font.drawInBatch(...)`.
- Also fixed: `MATRICES_PROJECTION_SNIPPET` → `MATRICES_FOG_SNIPPET`; `withVertexFormat`/`withSampler` → `withVertexBinding`/`withPrimitiveTopology`/`withBindGroupLayout`; `VertexFormat.Mode` → `PrimitiveTopology`; `Tesselator`/`RenderType.draw` removed; `getMainRenderTarget()` → `gameRenderer.mainRenderTarget()`; `getMainCamera()` → `mainCamera()`; `ComputeFov.usedConfiguredFov()` removed.

## 4. Migration Approach

- All former "get buffer → write → endBatch" code now uses `collector.submitCustomGeometry(poseStack, renderType, (pose, builder) -> { PoseStack ps = new PoseStack(); ps.last().set(pose); ... })`.
- The collector is threaded through deep render methods via the existing `ClientRenderHelper.FirstPersonArmHelper` `ThreadLocal<SubmitNodeCollector>` (a `getFirstPersonArmCollector()` getter was added), set at each render entry point and read internally.
- `TextRender` uses `collector.submitText(...)`.
- BEWLR `renderByItem` signatures changed `MultiBufferSource` → `SubmitNodeCollector`.
- `OculusCompat.endBatch` and its callers removed.

## 5. Known Runtime Risks

Deferred-submit ordering for `delegateRenderers` (nested submits), the scope stencil `visible` flag and the circle stencil mask (`renderOcularAndDivision`), and the (dead) custom `LaserBeamRenderState` pipeline were migrated for compilation and need in-game verification.
