## 根因

26.3 的 `SubmitNodeCollection#submitCustomGeometry` 会按 `RenderType#hasBlending()` 把自定义几何**分派到两个执行时机不同的阶段**：

```java
if (renderType.isOutline())            this.outline.submit(submit);
else if (renderType.hasBlending())     this.translucentCustomGeometry.submit(submit);
else                                   this.solid.submit(submit);
```

而 `FeatureRenderDispatcher.renderAllFeatures` 是 `executeSolid` → `executeTranslucent` 顺序执行。日志里实际执行的顺序正好印证了这一点：

```
0/ALWAYS_PASS/KEEP   1/GREATER_THAN/REPLACE   0/EQUAL/KEEP   1/EQUAL/KEEP   254/EQUAL/KEEP  ...  1/EQUAL/INVERT
                                                ↑ 黑色遮罩     ↑ 准心                    ↑ INVERT 圆被推到最后的 translucent 阶段
```

INVERT 圆用的是 `RenderTypes.debugTriangleFan()`，它的管线来自 `DEBUG_FILLED_SNIPPET`，带 `ColorTargetState(BlendFunction.TRANSLUCENT)` → `hasBlending() == true` → 被排进 translucent 阶段。而外环/镜身/黑色遮罩/准心用的 `entity_cutout_cull` 用的是 `ColorTargetState.DEFAULT`（无混合）→ 留在 solid 阶段。

于是执行顺序变成：先写目镜 → 镜身 → **黑色遮罩（此时圆还没翻转，遮罩盖满整个镜片）** → 准心（`GL_EQUAL 254`，此时还没有 254，全被丢弃）→ 最后才轮到 INVERT 圆。孔永远挖不出来。

`_clearStencilBuffer`、模板注入、`NO_DEPTH_TEST`（红点那个）都没问题 —— 纯粹是**阶段错位导致模板写入被排到模板测试之后**。

## 修法

`NO_COLOR_WRITE` 本来就只用在模板遮罩这两处（`renderOcularStencil` 的写入 + `renderOcularAndDivision` 的 INVERT 圆），而这两处都关了颜色写出。既然一个颜色都不写，混合就没有意义 —— 让 `NO_COLOR_WRITE` 顺手把混合函数也去掉，`hasBlending()` 就变 false，这些模板写入会回到 solid 阶段，与模板测试重新同阶段、顺序恢复。

这个改动是收敛的：`_colorMask` 全项目只在这两处用，其它带混合的模板绘制（比如 `entity_translucent` 的第一人称手臂）都是**模板测试**而非写入，跨阶段不影响，不会被误伤。

## 问题报告：26.3 目镜模板遮罩失效

### 症状

| 配件 | 症状 |
|---|---|
| 红点（`enableSight`） | 准心在 ocular 之外整片可见，待机时也能看到红点 |
| 4 倍镜（`enableScope`） | 目镜全黑（模型本身颜色），看不到孔 |

两者是**两个独立的根因**，恰好都出在 26.3 对「模板测试」的重构上。

---

### 根因一：模板测试被挪进 `DepthStencilState`（红点）

26.2 里模板测试是 `RenderPipeline` 上的独立字段，所以「整块移除深度状态」的修饰器不会连带抹掉模板。26.3 把模板塞进了 `DepthStencilState` 的第 5 个分量 —— 两者绑定在一起了。

`renderSight` 画准心前会 `_disableDepthTest()` → 推入 `NO_DEPTH_TEST`，其实现是 `withDepthStencilState(Optional.empty())`。模板随之消失，准心没了遮罩。

**修法**：在 `applyStencilToPipeline` 里，若管线已经没有深度状态，补一个等价的 `DepthStencilState(ALWAYS_PASS, writeDepth=false, …)` 只为把模板挂上去。

**没有直接改 `NO_DEPTH_TEST`**，这里有个坑值得记：GUI（`AttachmentCategorySlot` / `RefitTurnPageButton` 等）也用它，而 26.3 的 `GUI_SNIPPET` 不带深度状态、GUI 渲染通道因此**没有深度附件**，`FrontendRenderPass` 遇到 `wantsDepthTexture()` 为真的管线会直接抛 `IllegalStateException`。只在「确实有模板要挂」时才补状态，绕开了这个雷。同理 `NO_DEPTH_WRITE` 改写深度状态时必须显式带上 `stencilTest`。

---

### 根因二：自定义几何被拆进两个执行时机不同的渲染阶段（4 倍镜）

`SubmitNodeCollection#submitCustomGeometry` 按 `RenderType#hasBlending()` 分派：

```java

else if (renderType.hasBlending()) this.translucentCustomGeometry.submit(submit);
else                               this.solid.submit(submit);
```

