## 关键事实（都已比对）

**1. 开光影时屏幕上的雾来自深度缓冲，不是顶点距离**

Complementary 的雾算了两遍。除 gbuffers 里按顶点距离算的那次外，[deferred1.glsl:213/317] 在**延迟 pass 里**用 `depthtex0` 重建 viewPos 再跑一次 `DoFog`：

```glsl
float z0 = texelFetch(depthtex0, texelCoord, 0).r;
vec4 viewPos = gbufferProjectionInverse * (vec4(texCoord, z0, 1.0) * 2.0 - 1.0);
float lViewPos = length(viewPos);
DoFog(color, skyFade, lViewPos, playerPos, ...);   // ← 屏幕最终颜色由这里定
```

而 iris 的 `depthtex0` 就是主 target 的深度纹理（`IrisRenderingPipeline` 构造 `RenderTargets` 时传的是 `mainRenderTarget().getDepthTexture()`）。**所以屏幕上哪块雾重，完全取决于那块像素的深度是谁写的。**

**2. 雾的公式和阈值两版本完全一致**

- 原版 `FogRenderer` / `fog/environment/*` / `Camera`：26.2 vs 26.3 只差颜色由 `int` 变 `Vector3fc`，雾距离只依赖 render distance，**不含 FOV**。
- iris `FogUniforms` / `MixinFogRenderer` / `CameraUniforms` 反编译后逐字节相同；包里 `renderDistance = far`，`far` 在两版都是 `getEffectiveRenderDistance() * 16`。
- iris 26.3 相对 26.2 只有 15 个类有差异，全是 renderpearl 移植（`MixinGlRenderPipeline`、`MixinGlRenderPass`、`MixinRenderPass2`、`MixinPipelineBuilder`、`MixinGuiRenderer`、`IrisBindings`…），**没有一个是 fog 相关**。

→ 既然公式、阈值、uniform、原版参数都没变，「远到某个距离变纯色」和「镜内外不一样」就只能来自**深度缓冲的内容**变了。

**3. 26.3 确实变了的地方（都在 iris / 原版侧，不在 CGC）**

- **iris 26.3 重写了手部渲染**：`HandRenderer.renderSolid/renderTranslucent` 现在显式 `createRenderPass` 绑定 `mainRenderTarget()` 的 **color + depth**；26.2 只是 `featureRenderDispatcher.renderAllFeatures(collector)`，用当时绑定的 pass。`MixinItemInHandRenderer` 也从 `ItemInHandRenderer` 改指向 `FirstPersonHandsAndItemsRenderer`。
- **iris 26.3 去掉了两处把 `ImmediateState.isRenderingLevel` 置 true 的窗口**：26.2 有 `MixinCamera`（包 `Camera.update`）+ `MixinGameRenderer`（包 `extract`）+ `immediate/MixinLevelRenderer` 三处，26.3 只剩 `LevelRenderer.render` 一处。这个 flag 是 iris 反向 Z 补偿（`UndoReverseZThree/Four/Five`）和顶点格式扩展的总开关。（不过 `UndoReverseZTwo` 已经把 clip control 探测直接改成 `false`，所以这三处可能本来就只是兜底，优先级我排在后面。）

## 为什么会出现「ocular 里比 ocular 外重」

开镜时整屏都是放大后的世界（CGC 只改世界 FOV，所以倍率一致），但**目镜遮罩 / 镜身是手部 pass 里提交的 CGC 几何体**——它们在深度上贴着相机，而镜内圆孔里是世界的远深度。延迟 pass 按深度算雾时：

- 镜内（世界，远）→ 按距离满雾
- 镜外（枪体/遮罩覆盖处，近）→ 几乎无雾

这就是你看到的差异，它跟「ocular 里的雾距离算错了」无关，是**镜外那块像素的深度不是世界的深度**。26.2 看不到差别，说明 26.2 里 pack 拿到的深度状态和 26.3 不同——差异只可能出在上面那三条里（手部 pass 的渲染目标 / `isRenderingLevel` 窗口 / 新的 3D HUD 深度合成）。

## 机制：Border Fog 的距离来自「深度重建」，不是顶点距离

Complementary 的 Border Fog 长这样（`lib/atmospherics/fog/mainFog.glsl`）：

```glsl
// DoFog 里的调用（269 行）
DoBorderFog(color, skyFade, max(length(playerPos.xz), abs(playerPos.y)), ...);

// DoBorderFog（OVERWORLD）
float fog = lPos / renderDistance;   // renderDistance = far = 原版视距(区块)×16
fog = pow2(pow2(fog)); fog = pow2(pow2(fog));   // 总共 ^16
fog = 1.0 - exp(-3.0 * fog);
```

而 `playerPos` 在**延迟 pass** 里是从深度缓冲重建的（`deferred1.glsl:213-220`）：

```glsl
vec4 viewPos = gbufferProjectionInverse * (vec4(texCoord, z0, 1.0) * 2.0 - 1.0);
vec3 playerPos = ViewToPlayer(viewPos.xyz);
```

三点因此确定：

1. **^16 曲线**：距离只要错一点，雾就从 0 直接跳到 1 —— 这就是「过某个距离后变成雾一样纯色」看起来像硬边界的原因，而不是渐变。
2. **它和 Atmospheric Fog 是两套独立公式**，所以你把 Atmospheric Fog 调到 Very Subtle 几乎没用、关掉 Border Fog 就干净，完全符合预期。
3. **它算的是「深度重建出来的水平距离 ÷ 视距」**，不是「顶点距离 ÷ 视距」。所以 26.3 下这个比值被放大了，雾就会提前。

## 改了什么

[ClientRenderHelper.java](core/src/main/java/dev/xcolorful/customgun/client/util/ClientRenderHelper.java) —— 只动一个文件、一个函数：

```java
public static boolean DEBUG_NO_DEPTH_WRITE = true;   // ← 开关，false 即恢复原行为

public static RenderType bakePipelineState(RenderType renderType) {
    if (!DEBUG_NO_DEPTH_WRITE) {
        return RenderTypePipelineBake.bakePipelineState(renderType);
    }
    IStencilOperator stencilOperator = CustomGunClient.getStencilOperator();
    stencilOperator.pushPipelineModifier(PipelineModifier.NO_DEPTH_WRITE);
    try {
        return RenderTypePipelineBake.bakePipelineState(renderType);
    } finally {
        stencilOperator.popPipelineModifier();
    }
}
```

选这个点是刻意的：`bakePipelineState` 是**所有** CGC 手部几何体的唯一烘焙入口（枪体走 [ModelObject.java:200](core/src/main/java/dev/xcolorful/customgun/client/model/ModelObject.java:200)，瞄具目镜/镜身走 [_AttachmentModelRender.java:226](core/src/main/java/dev/xcolorful/customgun/client/model/_AttachmentModelRender.java:226)，模板圆扇走 :317）。所以开关一开，CGC 在手部 pass 里画的**全部**几何体都不写深度 —— 覆盖了「镜外那片屏幕是谁的深度」这个假设的所有可能来源。push/pop 用 try/finally 配平，嵌套调用（模板扇本来就在 `_depthMask(false)` 里）也不会错位。

## 时间线

1. **之前的修复** = 给 division 绘制包 `_disableDepthTest()` / `_enableDepthTest()`（现在你 core 里 `renderDivision` 的第一段）。目标就是你说的“不被地形裁掉”。
2. **这次的修复** = 在它基础上补第二遍“关颜色写入、开深度测试”，把深度写回去。只解决云/雾覆盖，**不改变裁切行为**——深度测试函数由第一段决定，第二段只是一遍不带颜色的重绘。

## 这个“关深度测试”在 1.20.1 到底有没有生效

之前那次修复的**有效性是按版本分的**：

- **1.21.6+**：`_disableDepthTest()` 走的是管线修饰器（`NO_DEPTH_TEST`），在 draw 时真正 `glDisable(GL_DEPTH_TEST)`，成立。
- **1.20.1**：`_disableDepthTest()` 是裸 `RenderSystem.disableDepthTest()`。但 1.20.1 的绘制状态是 RenderType 在提交时重新设的——`RenderType.end()` 在 `BufferUploader.drawWithShader` **之前**调用 `setupRenderState()`（[RenderType.java:426](D:/Github/Custom-Gun-Continued/core/build/tmp/.cache/expanded/zip_37945374cc85a8d63f479401391415e5/net/minecraft/client/renderer/RenderType.java:426)），而 `CompositeState` 默认 `LEQUAL_DEPTH_TEST`，它的 setup 无条件 `enableDepthTest(); depthFunc(515)`。所以那句 disable 在真正绘制时被覆盖了。

## 那 1.20.1 为什么没看到裁切

因为原版路径里根本轮不到它：无光影时 `GameRenderer` 在 `renderItemInHand` 之前刚 `RenderSystem.clear(256)` 清了深度（[GameRenderer.java:1131](D:/Github/Custom-Gun-Continued/core/build/tmp/.cache/expanded/zip_37945374cc85a8d63f479401391415e5/net/minecraft/client/renderer/GameRenderer.java:1131)），所以准心不存在被世界深度裁掉的条件。

有光影（Oculus）时手部被挪进 LevelRenderer、没有这次清深度，理论上才会露出裁切——也就是记忆里“1.20.1–26.1.2 疑似同源、发光点略暗、待验证”那条；而按上面 RenderType 的机制，那段 disable 在 1.20.1 上确实帮不上忙。

## 结论

- **第二遍不修裁切**：1.20.1 补上第二遍，裁切行为一模一样；第二遍只多写一次深度。
- **1.20.1 不需要第二遍**：它没有云/雾覆盖问题（无光影有清深度；Oculus 下即使有也是原问题）。
- 你真要让 1.20.1 在 Oculus 下也“不裁切 + 有深度”，靠的是之前说的 B 方案（自定义 `DepthTestStateShard`：`enableDepthTest()` + `glDepthFunc(GL_ALWAYS)`，一遍完成），而不是两遍。第二遍在 1.20.1 上无论加不加，都只是多画一次。

# 

对，`[1.20.1, 1.21.6)` 这层包了等于没包。三处源码可以闭合这个结论：

1. 这三个分支的 `_disableDepthTest()` 都是裸 `RenderSystem.disableDepthTest()`（1.21.1/1.21.4 的管线修饰器那半段在 `if (true) return;` 后面，编译掉了）。
2. 绘制时 RenderType 会重新设状态：1.21.4 是 `RenderType.draw(MeshData)` → `setupRenderState()`，1.21.1 同样；1.20.1 是 `RenderType.end()` → `setupRenderState()`。
3. `CompositeState` 默认 `depthTestState = LEQUAL_DEPTH_TEST`，`DepthTestStateShard` 的 setup 无条件 `enableDepthTest(); depthFunc(515)`；而内置 `NO_DEPTH_TEST`（func 519）的 setup 直接跳过，所以也不能靠换 shard 绕。

所以 1.20.1–1.21.4：**包不包，画面上完全一样**。这些版本没有云/雾变淡，恰恰是因为 disable 没生效——准心一直在按 LEQUAL 绘制并写深度，云和雾盖不上去。

## 建议

- **删掉没有视觉风险**。但如果要保持 core 统一，建议保留 helper 调用点，在 `[1.20.1, 1.21.6)` 分支里把那两句也当作版本专属实现处理（和现在第二遍用 `if (true) return;` 关掉的风格一致），而不是把调用点从 1.20.1 上移除。这样合并到其他分支时 diff 只落在版本块里。
- **别把这个结论外推到 1.21.6+**：那里 `_disableDepthTest` 走的是管线修饰器，真正生效，必须保留；第二遍也必须保留。
- **如果目标是在 1.20.1–1.21.4 也做到“准心不被世界裁”**，这层帮不上（它从来没生效过），需要 B 方案的自定义 `DepthTestStateShard`（`enableDepthTest()` + `glDepthFunc(GL_ALWAYS)`，一遍同时满足恒过和写深度）。不过无光影时原版在 `renderItemInHand` 前会清深度，本来就没有裁切条件。

一个仍未验证的点：这些版本开光影时，Iris/Oculus 到底是把手部画在关卡内还是关卡后——这决定“有没有裁切”本身存不存在。我们只确认了 disable 无效，没有实机确认裁切现象。
