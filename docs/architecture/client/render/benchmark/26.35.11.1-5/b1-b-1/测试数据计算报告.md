# 测试数据计算报告（CGC 1.20.1 · b1-b-1：换弹后的待机帧时间）

**数据**：本目录 4 次独立启动（n=4），每次含 Afterburner 与 F12 两段，时间不重叠。
- `cgc1 (N).txt`：Afterburner 5 步 = 空手 / ak47 换弹前 / ak47 换弹后 / m4a1 满配换弹前 / m4a1 满配换弹后
- `cgc1-builtin (N).txt`：F12 2 段 = ak47 换弹 / 满配换弹（每段 10 s，0/3/6 秒各换一次弹）

**口径**：帧时间 = 1000 / FPS；均值 ± 1 样本标准差；「换弹后 − 换弹前」按逐文件配对相减。F12 段帧时间含探针开销，不参与帧时间结论。
**环境**：GTX 1660 SUPER / i5-9400F / 1080p165；Forge 47.4.23 + Embeddium + Oculus（未开光影包）；超平坦虚空、无展示框、渲染距离 2；见 [标准.txt](./标准.txt)。
**复现**：`python analyze.py`。

## 1. 帧时间

|步骤|AF 帧时间|1% low|
|---|---:|---:|
|空手|0.778 ± 0.033 ms（1284.8 FPS）|532.0|
|ak47 换弹前|0.970 ± 0.022（1031.3）|464.2|
|ak47 换弹后|**0.992 ± 0.015**（1007.9）|472.3|
|满配 换弹前|1.291 ± 0.035（774.5）|415.2|
|满配 换弹后|**1.317 ± 0.023**（759.5）|419.4|

「换弹前」与 `26.35.11.1-5` 的静止值一致（0.991 / 1.330），本批测试环境复现了上一批的基线。进档时的装备动画是否切过块无法从数据里单独分离（两批都含装备动画），但内置动画几乎都只驱动 root / 少数固定节点，即使切过也是任何动画都会触发的同一组切块——因此这里的「前」就是实际游玩会遇到的稳态起点，不是被污染的绝对值。

## 2. 换弹后 − 换弹前（逐文件配对）

|枪型|差值|比例|逐次|
|---|---:|---:|---|
|ak47|**+0.023 ± 0.024 ms**|+2.3%|[0.002, 0.007, 0.025, 0.056]|
|m4a1 满配|**+0.026 ± 0.037 ms**|+2.0%|[−0.004, 0.077, 0.028, 0.002]|

- 换弹把脏骨骼切成新块之后，静态待机多出 **0.02–0.03 ms（约 2%）**，折合约 3 次 8 µs 的 draw（更小的块单次 draw 更便宜，实际块数可能更多）。
- 幅度远小于「遍历/上传」级别的成本：块一旦切开，动画帧只换矩阵，静态帧只付每块一次 draw。
- **换弹是脏集的上界**（开火只驱动栓与整枪，检视是换弹的慢放且通道更少），所以这就是长时间游玩后拓扑饱和时的稳态，不会随会话继续增长。
- 1% low 没有下降（464.2 → 472.3、415.2 → 419.4），额外 draw 不影响掉帧。

## 3. 换弹段的探针旁证（F12，10 s / 3 次换弹）

|项|ak47|满配|
|---|---:|---:|
|CGC|0.323 ± 0.023|0.552 ± 0.017|
|Model render total|0.239 ± 0.008|0.400 ± 0.009|
|`Draw calls`|21.05 ± 0.01|42.61 ± 0.02|
|`Bake rebuilds`|**0.00**|**0.00**|
|`Static bake`（单次）|0.343 ± 0.015 ms|0.657 ± 0.027 ms|
|`Cubes submitted`|90.3 ± 0.3|46.1 ± 0.3|
|`Distinct RenderTypes`|1|6|

- 3 次换弹的整段只烘了首次切开骨架的那几帧，`Bake rebuilds` 均值为 0；之后两次换弹零重建。
- `Draw calls` 是**整段平均**（混有换弹前/后的拓扑），不能当作换弹后的值；换弹后的 draw 增量由第 2 节的帧时间差间接给出。
- 与 `26.35.11.1-5` 的换弹段一致（CGC 0.319 / 0.570，`Draw calls` 21.3 / 43.0），本批没有回归。

## 4. 结论

1. **换弹后的静态帧时间只涨约 2%（0.02–0.03 ms）**，不存在「动画播放后帧数明显下降」。
2. 原因是切块只增加少量小块 draw，而省下的遍历与上传是数量级的；换弹作为脏集上界，饱和值就是这两组数。
3. 拓扑只增不减是有代价的，但在 1.20.1 的这个场景里代价是 2%，低于测量噪声的两倍；若后续要压缩，见 [TODO](../../TODO.md) 的「分块 draw 数」待评估项。

## 5. 说明

- 第 2 节的 sd 比差值本身还大（满配 +0.026 ± 0.037），说明逐次波动主要来自进程噪声；两次都为正、且 5 次测量里 4 次为正，方向可信。
- 满配第 2 次启动的 +0.077 ms 是最大离群点；ak47 第 4 次 +0.056。去掉离群后比例仍在 1.5%–2%。
- F12 段本身含探针开销与换弹，不与前后两次 Afterburner 帧数合并。
