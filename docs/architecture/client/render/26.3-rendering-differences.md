# 26.2 → 26.3 渲染系统差异参考

> 用途同 [26.2 渲染系统差异参考](./26.2-rendering-differences.md)：只记录**原版 API 变更**与「去哪找源码」，
> 不记录本次移植改了什么（那见 [b1a 实施记录](./refactor/b1a-static-bake.md)「26.3」）。
> 反编译源：`<worktree>/core/build/neoForm/neoFormJoined26.3-1/steps/transformSource/transformed/`。

---

## 一、后端拆分：blaze3d → renderpearl

| 旧 (26.2) | 新 (26.3) |
|---|---|
| `com.mojang.blaze3d.pipeline.RenderPipeline` / `ColorTargetState` / `DepthStencilState` / `BlendFunction` | `com.mojang.renderpearl.api.pipeline.*` |
| `com.mojang.blaze3d.PrimitiveTopology` | `com.mojang.renderpearl.api.pipeline.PrimitiveTopology` |
| `com.mojang.blaze3d.shaders.UniformType` | `com.mojang.renderpearl.api.pipeline.UniformType` |
| `com.mojang.blaze3d.vertex.VertexFormat` / `VertexFormatElement` | `com.mojang.renderpearl.api.vertex.*` |
| `com.mojang.blaze3d.opengl.GlStateManager` | `com.mojang.renderpearl.backend.opengl.GlStateManager` |

仍在原位：`blaze3d.pipeline.RenderTarget`、
`blaze3d.vertex.{BufferBuilder, ByteBufferBuilder, MeshData, PoseStack, VertexConsumer, DefaultVertexFormat}`、`blaze3d.systems.RenderSystem`。

## 二、管线与状态

- `RenderPipeline#getColorTargetState()`（单数）删除，只剩 `getColorTargetStates()`，返回 `List<@Nullable ColorTargetState>`。
- 模板测试从管线的独立字段（`getStencilTest()` / `withStencilTest()`）挪进 `DepthStencilState` 的第 5 个分量 `stencilTest`；
  4 参构造器会把它置 `null`，改写深度状态时必须显式带上模板。
- `RenderSystem#applyPipelineModifiers(RenderPipeline)` 删除；修饰器栈 `PIPELINE_MODIFIERS` 变私有，
  只有 `PipelineModifierStack#apply` 会执行修饰器（同时被 `RenderSystem#getCompiledPipelineNullable` 与
  `RenderTypePipelineBake` 调用）。
- `RenderSetup` 变为不可变、构造器私有：`OutputTarget` 被 `OitPipelineSet`（字段 `oitPipelineSet`）取代，
  新增 `outlineTextureName` / `forceSolidModelPhase`，构造参数顺序随之变化。
- `RenderType` 提供 `format()` / `primitiveTopology()`，烘焙按它们取顶点格式与拓扑。

## 三、延迟渲染的执行时机

- `SubmitNodeCollection#submitCustomGeometry` 按 `RenderType` 分派：`isOutline()` → outline；
  `hasBlending()` → `translucentCustomGeometry`；否则 → `solid`。
  `FeatureRenderDispatcher#renderAllFeatures` 依次执行 solid → translucent → translucentAfterTerrain → …，
  **模板写入不能带混合**，否则会被排到模板测试之后执行（典型：目镜 INVERT 圆用带 `TRANSLUCENT` 的 `debugTriangleFan` →
  4 倍镜目镜全黑）。`forceSolidModelPhase` 对 custom geometry 无效，那个分支只看 `hasBlending()`。
- 管线预编译会校验「着色器用到的每个 uniform / sampler 都在管线的 bind group layout 里声明」
  （`com.mojang.renderpearl.frontend.shaders.PipelineBuilder#generateBackendCreateInfo`）。
  缺了会在资源重载时抛 `ShaderCompileException: Unable to find shader defined uniform (SamplerN)` → 启动黑屏。
  例：26.3 的 `core/entity.vsh` 里 `Sampler1` 只被 `#ifndef NO_OVERLAY` 守卫，基于 `ENTITY_EMISSIVE_SNIPPET`
  的自定义管线要补 `BindGroupLayouts.SAMPLER1`（vanilla 的 `ENTITY_TRANSLUCENT_EMISSIVE` 同样补了）。
- `RenderPipelines.TEXT_SNIPPET` 不再自带 `ColorTargetState`，自定义文字管线必须显式 `.withColorTargetState(...)`，
  否则管线是 0 个颜色目标，画进 RenderPass 时抛颜色附件数量不匹配。

## 四、着色器源

- 26.3 用 shaderc 把 GLSL 编译成 SPIR-V（`renderpearl.frontend.shaders.GlslCompiler`），着色器写法随之改变：
  - `#version 330` + `#extension GL_ARB_separate_shader_objects : require`；
  - `#moj_import <...>` **不再支持**，改用 `#include <minecraft:...>`（`ShaderSource` 的 include 回调按 `Identifier` 解析）；
  - 顶点输入、阶段间 varyings 都要显式 `layout(location = N)`。
- 注册为 **required** 的自定义管线（`RegisterRenderPipelinesEvent#registerPipeline`）会在资源重载时全部编译，
  任一失败就抛 `Failed to load required shader programs` → 启动黑屏；只用于兜底的管线可用 `registerOptionalPipeline`。
- 顶点写入：`VertexConsumer` 新增抽象方法 `setUv3(float, float)`；任何自定义 `VertexConsumer` 实现都要补上。

## 五、其它（本次烘焙移植未直接涉及）

- `ItemInHandRenderer` 删除：状态拆到 `FirstPersonHandsAndItems`（由 `LocalPlayer#firstPersonHandsAndItems()` 持有），
  渲染器为 `FirstPersonHandsAndItemsRenderer`；`submitHandsWithItems` 改为
  `(float, PoseStack, SubmitNodeCollector, PlayerRenderState, FirstPersonHandsAndItemsRenderState)`。
- `PoseStack#mulPose(Quaternionfc)` 改名 `rotate(Quaternionfc)`（实现完全一致）。
- `FeatureRenderDispatcher#renderAllFeatures` 变为 `static (RenderPass, PreparedFrame)`；
  `GameRenderer#renderLevel` 无参；`LevelRenderer#render` 7 参。

# English

# 26.2 → 26.3 Rendering Differences

> Same purpose as the [26.2 reference](./26.2-rendering-differences.md): **vanilla API changes** and where to find the sources only,
> not what this port changed (see [b1a implementation notes](./refactor/b1a-static-bake.md) "26.3").
> Decompiled sources: `<worktree>/core/build/neoForm/neoFormJoined26.3-1/steps/transformSource/transformed/`.

## Backend split: blaze3d → renderpearl

`RenderPipeline` / `ColorTargetState` / `DepthStencilState` / `BlendFunction` / `PrimitiveTopology` / `UniformType` moved to
`com.mojang.renderpearl.api.pipeline.*`; `VertexFormat` / `VertexFormatElement` moved to `com.mojang.renderpearl.api.vertex.*`;
`GlStateManager` moved to `com.mojang.renderpearl.backend.opengl.*`.
`RenderTarget`, `BufferBuilder`, `ByteBufferBuilder`, `MeshData`, `PoseStack`, `VertexConsumer`, `DefaultVertexFormat`
and `RenderSystem` stay in `blaze3d`.

## Pipelines and state

- `RenderPipeline#getColorTargetState()` is gone; use `getColorTargetStates()` (`List<@Nullable ColorTargetState>`).
- The stencil test moved into `DepthStencilState` (5th component `stencilTest`); the 4-arg constructor leaves it `null`.
- `RenderSystem#applyPipelineModifiers` is gone; `PIPELINE_MODIFIERS` is private and only `PipelineModifierStack#apply` runs modifiers.
- `RenderSetup` is immutable with a private constructor: `OutputTarget` → `OitPipelineSet`, plus `outlineTextureName` /
  `forceSolidModelPhase`; constructor argument order changed.
- `RenderType` exposes `format()` / `primitiveTopology()`.

## Deferred-phase timing

- `SubmitNodeCollection#submitCustomGeometry` dispatches on the `RenderType`: outline → outline, `hasBlending()` →
  `translucentCustomGeometry`, otherwise → `solid`. `FeatureRenderDispatcher#renderAllFeatures` runs solid before translucent,
  so **stencil writes must not blend**, or they execute after the stencil test. `forceSolidModelPhase` does not affect
  custom geometry (that branch only checks `hasBlending()`).
- Pipeline precompilation validates that every uniform/sampler used by the shader is declared in the pipeline's bind group layout;
  a missing one fails resource reload with `ShaderCompileException` and boots to a black screen.
- `RenderPipelines.TEXT_SNIPPET` no longer carries a `ColorTargetState`; custom text pipelines must add one explicitly.

## Vertex writing and shader sources

`VertexConsumer` gained an abstract `setUv3(float, float)`; every custom implementation must override it.

26.3 compiles GLSL to SPIR-V with shaderc: use `#version 330` + `GL_ARB_separate_shader_objects`,
`#include <minecraft:...>` instead of `#moj_import`, and explicit `layout(location = N)` on inputs and varyings.
Required pipelines are all compiled on resource reload; any failure throws `Failed to load required shader programs`
and boots to a black screen.

## Other

`ItemInHandRenderer` was split into `FirstPersonHandsAndItems` (state) and `FirstPersonHandsAndItemsRenderer`;
`PoseStack#mulPose(Quaternionfc)` is now `rotate`; `FeatureRenderDispatcher#renderAllFeatures` is `static (RenderPass, PreparedFrame)`.
