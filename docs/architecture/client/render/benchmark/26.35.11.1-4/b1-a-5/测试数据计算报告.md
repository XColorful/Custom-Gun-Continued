# 测试数据计算报告（CGC 1.20.1 · b1-a-5：B1-b 前置探针）

**数据**：本目录 4 组文件，每组 = 一次独立启动（n=4）。每组内含 Afterburner 与 F12 内置探针两次运行，**时间上不重叠**（先 AF 10 s，再 F12 10 s）。
- `cgc1 (N).txt`：第一人称 4 步 = 空手 / `tacz:ak47` 裸配 / `tacz:m4a1` 裸配 / `tacz:m4a1` 满配
- `cgc1-builtin (N).txt`：同 4 步的 F12 探针
- `cgc1-multi (N).txt`：multi 3 步 = 9 个 m4a1 满配展示框（空手）/ +第一人称 m4a1 裸配 / +第一人称 m4a1 满配
- `cgc-multi-builtin (N).txt`：同 3 步的 F12 探针

**口径**：帧时间 = 1000 / FPS；均值 ± 1 样本标准差。Afterburner 与 F12 分开，F12 采集期的帧时间不计入帧时间结论（它含探针开销）。`Draw calls` 为整帧 `drawWithShader` 计数，含非 CGC 的 8 次基线，CGC 部分按差值计。
**环境**：GTX 1660 SUPER / i5-9400F / 1080p165；Forge 47.4.23 + Embeddium + Oculus（未开光影包）；超平坦虚空、渲染距离 2、模拟距离 5；见 [标准.txt](./标准.txt)。
**复现**：`python analyze.py`。

> 与 [`26.35.11.1-3`](../26.35.11.1-3/测试数据计算报告.md) 可直接对照：同为 m4a1 裸配 / 满配的第一人称与满配 multi 场景。

## 2. 脏节点比例（B1-b 的输入）

|场景|Distinct nodes|Dirty nodes|脏节点比例|
|---|---:|---:|---:|
|第一人称 ak47|361|0.982 ± 0.005|**0.27%**|
|第一人称 m4a1 裸配|612|0.982 ± 0.005|**0.16%**|
|第一人称 m4a1 满配|1,577|0.988 ± 0.005|**0.06%**|

- 静止视角下每帧只有 **1 个节点**改变（根节点的视角 bob），12–14 条动画通道的值已收敛。
- 这意味着 B1-b 的「脏子树重写」在空闲场景能跳过 **99.7%–99.9%** 的遍历；按 0.798 ms 的满配遍历计，残留只有微秒级。
- **这是下界**：开火、换弹、检视时动画会大面积改写节点，本批协议保持静止，未测该状态。B1-b 的验收应再补一组「开火/换弹中」的采集。
- multi（烘焙路径）`Distinct nodes = 0` 属预期：静态实例不经 `BedrockPart.render`，与 `State changes = 0` 一致。

## 3. multi：draw、RenderType 与 GPU 归因

|项|9 满配展示框|+第一人称裸配|+第一人称满配|
|---|---:|---:|---:|
|AF 帧时间|**2.146 ± 0.053 ms**|3.082 ± 0.048|**4.133 ± 0.041**|
|CGC（探针）|**1.199 ± 0.022**|2.019 ± 0.034|2.925 ± 0.043|
|`endBatch draw`|0.629 ± 0.014|0.677 ± 0.023|0.698 ± 0.014|
|瞄具模板|0.349 ± 0.008|0.363 ± 0.013|0.972 ± 0.017|
|delegate|0.405 ± 0.005|0.491 ± 0.009|0.789 ± 0.008|
|CGC GPU busy|0.260 ± 0.008|0.489 ± 0.006|0.262 ± 0.008|
|Draw calls|**81**（9×9）|86|101|
|Distinct RenderTypes|**6**|6|6|
|Bake rebuilds|**0**|0|0|
|Upload bytes|30.8 KB|682 KB|1.54 MB|

- **B1-a 在满配 multi 上成立**：每枪 CGC 1.199 / 9 = **0.133 ms**（重构前 1.434，−90.7%）；帧时间 14.723 → **2.146 ms**（−85.4%）。稳态 `Bake rebuilds = 0`、`Upload bytes` 只剩模板窗口的 30.8 KB，烘焙缓存没有每帧失效。
- **B2 的下限是 6**：全场景不同 `RenderType` 只有 6 个，81 次 draw 可压到约 6 次。单次 draw 0.629 / 81 = **7.8 µs**。
- **B2 后的地板比方案预估高**：`CGC 1.199 − draw 0.629 + 6×0.0078 ≈ **0.62 ms**`。方案里 B1-a 后瞄具模板估 0.05 ms，实测 **0.349 ms**（每枪 0.039），模板 pass 不参与合批，因此 multi 的 CGC 地板由它主导。按此推算 B2 后帧时间 ≈ **1.56 ms**，仍满足 ≤1.6 ms 目标，但没有余量。
- **0.97 ms「未归因项」有答案了**：multi 帧时间 2.146 − CGC 1.199 = **0.947 ms**，与 `b1-a-2` 的空展示框场景基线 0.866 ms 同量级；CGC 的 GPU 时间只有 0.260 ms。它**不是 CGC 的 GPU 绘制成本，而是场景/引擎基线**。本批没有「9 个空展示框」的一步，这一点是按基线量级推断的，下一批建议补一步坐实。

## 4. `CGC GPU busy` 的口径限制

- 第一人称（队列浅、CPU 提交快）可信：裸配 0.103 ms、满配 0.419 ms，占 CGC 的 5%–22%，**第一人称仍是 CPU 受限**。
- multi 下该值反而更低（0.260，低于单场景满配的 0.419），且 `+满配` 一步与 `空手` 几乎相同（0.262 vs 0.260）。原因是在 CPU 受限的深队列里，`GL_TIME_ELAPSED` 的分段边界会与 GPU 执行错位，**深队列下这个口径只能当量级参考，不能相减**。
- 开光影时 `endBatch` 是入队语义，该值本就不可信；本批未开光影。

## 6. 对 B1-b / B2 的影响

1. **B1-b 的脏子树方向成立**：空闲时脏节点 0.06%–0.27%，遍历 0.519 / 0.798 ms 可基本消除；但必须补测开火/换弹状态。
2. **B1-b 的满配残留需要重新审视**：满配 CGC 1.916 的构成是 遍历 0.798 + 模板 0.713 + flush 0.406 + delegate 0.428。模板从烘焙网格重放后能剩多少，本批只能给出静态展示的参照——每窗口 0.039 ms，第一人称一次开镜有 5 个模板 pass，按此推算约 0.2 ms，而不是方案里的 0.06；若 delegate 内部主要是附件模型遍历，B1-b 可进一步把它压到 0.1 左右，目标 0.45–0.60 仍有可能，但取决于这一点。
3. **B2 目标不变、地板要上调**：帧时间 ≤1.6 ms 仍可达（推算 1.56），CGC 地板从 0.25–0.35 修正为 **≈0.6**，原因是静态瞄具模板 0.349 ms 不参与合批。

## 7. 异常与说明

- `+第一人称 m4a1 裸配` 的 `State changes` 为 0 而 `Dirty nodes` 为 0.985：展示框与手持枪共享模型实例，帧内第一次提交（静态展示，基础姿态）已写入指纹，之后的手持提交按帧去重不再重算。`State changes` 在混合场景下会低估，**脏节点以 `Dirty nodes` 为准**。
- 第一人称 ak47 的 1% low（291.8）低于更重的 m4a1 裸配（400.5），属进程级噪声，不影响均值结论。
- 第一人称 m4a1 裸配的 `GPU frame busy` 标准差偏大（1.013 ± 0.566），其中一次采集含 7 ms 的尖峰；该行只作参考。
- multi 的 `Draw calls` 中 CGC 部分为 81 = 9 枪 × 9 次，但手持枪的增量为 5 / 20，与第一人称单场景的 4 / 19 差 1 次，属非 CGC draw 的基线差异（手臂/文字），不代表 CGC 多了一次 draw。
