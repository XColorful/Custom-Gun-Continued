## 为什么不能沿用整模烘焙

第一人称每个节点每帧都被动画改写，整模指纹每帧都变，整模烘焙等于每帧全量重烘（与即时管线同价）。B1-b 把模型切成若干**块**：

- 顶层节点是块根，**自身变换提升为绘制矩阵**，动画写根不产生重烘焙；
- 其余节点首次变脏时在它所在块上**切开**，之后只重烘焙脏节点自己的子树；
- 静态部分留在剩余的大块里，稳态下不重烘焙。

实测（[`b1-a-7`](../benchmark/26.35.11.1-4/b1-a-7/测试数据计算报告.md)、[`b1-a-8`](../benchmark/26.35.11.1-4/b1-a-8/测试数据计算报告.md)）：静止时只有根在动；换弹时脏节点峰值 9–14，脏 cube 占比 p99 为 44.0% / 20.7% / 9.3%（ak47 / 裸配 / 满配），满配仍有 91% 的遍历可跳过。

## 分块规则

|节点|处理|
|---|---|
|顶层节点（`parent == null`）|块根；自身变换只进绘制矩阵|
|其余被动画 / 状态段改写的节点|切块根；自身变换只进绘制矩阵|
|块内普通节点|顶点烘进块网格（含自身变换）|
|functional 回调**直接发射几何**的节点|整棵子树改为即时绘制（见下）|

- 块网格**不含块根自身**的平移 / 旋转 / 缩放 / 可见性：变换由矩阵承担，可见性在绘制时按祖先链剪枝。
  因此动画驱动块根永远不触发重烘焙。
- 块网格以「块根之下、没有被其它块切走」的部分为范围，块根之间的父子关系不重叠。
- 绘制顺序按节点树的 DFS 前序，与即时遍历的提交顺序一致。

## 失效条件

|触发|处置|
|---|---|
|状态段逐节点比较 `stateHash()`（变换 + `visible` + 是否被替换渲染）发现变化|在脏节点处切块（或重建它所在的块）|
|块的祖先不可见 / 被替换渲染|本帧跳过该块并标脏，重新可见时重建（隐藏期间状态段看不到子树变化）|
|`light` / 顶点格式（光影）变化|换键重建该块|
|资源重载|`StaticBakeCache.clearAll()` 一并释放全部分块网格|
|烘焙网格被关闭|本帧跳过并标脏，下一帧重建|

单块网格按 `(RenderType, light, overlay, 是否光影, 颜色)` 缓存最多 4 份：光影的阴影 pass 会换一套光照（有时还换顶点格式），不能只留一份；超出时淘汰最久未用的一条。

## 单节点退回（MAG_ADDITIONAL）

状态段逐节点统计 functional 回调往 consumer 写了多少顶点。写过的节点标记为**即时块**：

- 该节点整棵子树不再烘焙，每帧走 `BufferSource` 即时绘制并立即 flush；
- 不再触发「整个模型退回即时管线」——B1-a 里这条会让换弹帧（最需要脏子树优化的时候）整帧失效。

内置回调中只有 `MAG_ADDITIONAL` 属于这一类；它的回调是幂等的，因此状态段与绘制段各执行一次没有副作用。

## 瞄具模板

`_AttachmentModelRender#renderModelPart` 把**路径前缀变换提升为绘制矩阵**，网格只按「目标节点子树」缓存：

- 枪身骨骼（瞄具定位组等）每帧被动画驱动时，瞄具网格仍然可以直接复用；
- 模板窗口、目镜环、镜身、准心各 pass 的绘制时机与 GL 状态不变，只是顶点不再逐帧生成。

## 退回即时管线的情况

1. **没有可用着色器**：`StaticBake.available()` 在状态段之前判断（无光影且 `cgc_baked_entity` 未注册、没装 `cgccshader` 的光影环境），整模走即时管线，functional 回调不会执行两次。
2. **网格绘制失败**：本帧不重复绘制（已画出的部分保留），标脏后下一帧重建。
3. **关掉 `StaticBake.ENABLED`**：与重构前完全一致，用于实机 A/B（同时关闭展示框烘焙）。

## 已知限制

- **光照烘进顶点**：`light` 变化（走到不同亮度区域）会重建受影响的块，换一次光照等价于付一次即时遍历的成本；稳态仍是 0 重建。与 B1-a 相同。正在按 [B1-c 光照解耦](./lighting-decoupling.md) 移除，届时缓存键不再包含 `light`。
- **块的拓扑只会变多**：出现过一次动画的节点会一直是块根，即使之后不再动。块数上限由「实际被动画驱动过的节点数」决定；每块每帧多一次 draw。
- **不支持运行时增删父子节点**：块缓存了祖先路径，addon 在加载完成后改层级需要触发模型重新加载。
- **回调直接发射几何的节点**会让整棵子树失去烘焙收益，属于制作期约束（见 [方案 B 的美术制作约束](./scheme-b-baked-mesh.md#美术制作约束)）。
- **半透明枪**：块是多次 draw，块间的绘制顺序按 DFS 但不再是单次提交内的顶点顺序；光影下委托可能被延迟重放，与分块直接绘制的相对顺序也和即时管线不同。深度写入语义不变，风险与 B1-a 相同。
- 未实现：`StaticBake.FORCE_REBUILD` 只影响整模烘焙，分块路径靠脏状态自然重建。

## 探针

沿用现有探针，语义有几处变化：

|探针|B1-b 后的含义|
|---|---|
|`Bake rebuilds`|分块重建次数；稳态为 0，只有脏子树 / 光照变化时非 0|
|`Cubes submitted`|只在烘焙时累加，稳态接近 0|
|`Draw calls`|每块一次（静态展示仍是一次）|
|`Geometry traverse`|即时管线专用；分块路径不再经过|
|`Distinct / Dirty nodes` / `Dirty subtree nodes`|只统计即时块与即时管线；分块路径的脏集改由 `Bake rebuilds` 直接反映|
|`endBatch calls` / `Upload bytes`|只统计即时块与委托|

## 验收清单（人工，开 / 关光影各一次）

1. **画面**：枪体、弹匣、枪机、握把、枪托、瞄具各部件位置与姿态正确；静止时与 `ENABLED = false` 完全一致。
2. **换弹**：弹匣替换、附加弹匣出现 / 消失、枪机动作正确；换弹期间不应整帧退回即时管线（`Cubes submitted` 峰值只来自脏子树）。
3. **开火 / 检视 / 切枪**：栓与整枪动作正确（整枪走根矩阵，不重建）。
4. **瞄具**：开镜、模板遮罩、目镜环、准心、切换瞄具视野正常；换枪 / 换配件后瞄具内容立即更新。
5. **光影**：Oculus 开关光影包下画面一致；切换光影包不应残留一帧旧格式。
6. **探针**：静止时 `Bake rebuilds` 稳态为 0；走动换光照时允许瞬时非 0。
