## 先纠正我的错误：26.3 不设 OIT set 会崩

我之前说「自定义几何体不读 `oitPipelineSet`，不设也不会炸」是错的。实读 26.3 源码：开「改进透明」时 `SubmitNodeCollection` 把 `translucentCustomGeometry` 直接指向 `oitTranslucent` 阶段，`RenderTypeFeatureRenderer.executeGroup` 会带非 null 的 `OitStage` 走 `PreparedRenderType.drawFromBufferOit`，而它开头就是：

```java
if (this.oitPipelineSet == null)
    throw new IllegalStateException("Render type " + this.name + " does not have OIT pipelines set up.");
```

所以 26.3 的 `LASER_BEAM` / `LASER_BEAM_ENTITY` 现在配了 `setOitPipelines(...)`：`OIT_PARTICLE` / `OIT_ENTITY_EMISSIVE`（后者对应我们那条 emissive 实体管线）。

还有一条连带的硬约束：**OIT set 的顶点格式必须和主管线格式一致**（staged buffer 按主管线格式写、draw 时按 OIT 管线格式解释），所以 26.3 的主管线的顶点格式从 `POSITION_COLOR_TEX_LIGHTMAP` 换成了 `DefaultVertexFormat.PARTICLE` —— 属性集完全相同（Position/UV0/Color/UV2）、只有顺序不同，`BeamRender` 是按语义 `setColor/setUv/setLight` 写的，不用改代码。顺带一个佐证：**26.3 里 `POSITION_COLOR_TEX_LIGHTMAP` 已被 vanilla 彻底弃用**（`RenderPipelines`/`RenderTypes` 里 0 处引用）。
