# 1.21.11 → 26.1.x 渲染系统差异参考

> 用途同 [26.2 渲染系统差异参考](./26.2-rendering-differences.md)：只记录**原版 API 变更**与「去哪找源码」，
> 不记录本次移植改了什么（那见 [b1a 实施记录](./refactor/b1a-static-bake.md)「26.1.x」）。
>
> 26.1.x 仍是即时提交，渲染状态的载体（`RenderType` = `RenderPipeline` + `RenderSetup`、自建 `RenderPass`）
> 与 1.21.11 相同；差异集中在个别 builder 方法与顶点格式常量。

---

## 逐项 API 变更

| 旧 (1.21.11) | 新 (26.1.x) | 去哪找 |
|---|---|---|
| `RenderType` / `RenderSetup` / `RenderPipeline` 的结构与字段 | 不变（含 `getTextures()` 惰性上传的行为） | `.../rendertype/RenderType.java`、`RenderSetup.java` |
| `RenderPipeline.Builder#withUniform(name, UniformType)` | **仍在**；26.1.x 尚未 renderpearl，`UniformType` 位于 `com.mojang.blaze3d.shaders` | `com.mojang.blaze3d.pipeline.RenderPipeline` |
| `RenderPipeline.Builder#withBlend(BlendFunction)` | 移除；改 `withColorTargetState(new ColorTargetState(blend))` | 同上，`com.mojang.blaze3d.pipeline.ColorTargetState` |
| Builder 未设 `depthStencilState` 时 | 默认从「LEQUAL + 写深度」变成 `null`（`applyPipelineState` 里等价于关深度测试）；需要时显式 `DepthStencilState.DEFAULT` | 同上 |
| `DefaultVertexFormat.NEW_ENTITY` | `ENTITY`（元素布局相同） | `com.mojang.blaze3d.vertex.DefaultVertexFormat` |
| `VertexFormatElement.Usage`、`getUsage()` / `usage()` | 移除；元素改具名常量 `UV0` / `UV1` / `UV2` 等，只剩 `index()` / `type()` / `byteSize()` | `com.mojang.blaze3d.vertex.VertexFormatElement` |
| `RenderTypes.entityCutout(t)`（面剔除） | `entityCutout` 改为**不剔除**；剔除用 `entityCutoutCull(t)` | `.../rendertype/RenderTypes.java`、`RenderPipelines.ENTITY_CUTOUT*` |
| `RenderTypes.itemEntityTranslucentCull(t)` | 移除；`entityTranslucentCullItemTarget(t)` = `ENTITY_TRANSLUCENT_CULL` + `OutputTarget.ITEM_ENTITY_TARGET` | 同上 |
| `Player#displayClientMessage(Component, boolean)` | 拆成 `sendSystemMessage(Component)`（聊天）与 `sendOverlayMessage(Component)`（物品栏上方） | `net/minecraft/world/entity/player/Player.java` |

### 烘焙路径相关

- `CgcBaked` 在 26.1.x 照旧走 `withUniform(..., UNIFORM_BUFFER)`，派生管线各自声明的结论不变；真正的移除点是 26.2 的 renderpearl。
- 判断「uv2 元素」：`element == VertexFormatElement.UV2`（注册单例），不再有 usage 判定。
- `RenderSetup#getTextures()` 会按需上传纹理：**建 pass 之前**取贴图，与 1.21.11 相同。

# English

# 1.21.11 → 26.1.x Rendering Differences

> Same purpose as the [26.2 reference](./26.2-rendering-differences.md): **vanilla API changes** and where to find the sources only,
> not what this port changed (see [b1a implementation notes](./refactor/b1a-static-bake.md) "26.1.x").
>
> 26.1.x is still immediate-mode; the state carrier (`RenderType` = `RenderPipeline` + `RenderSetup`, hand-built `RenderPass`)
> is the same as 1.21.11. Differences are limited to a few builder methods and vertex-format constants.

| Old (1.21.11) | New (26.1.x) | Where |
|---|---|---|
| `RenderType` / `RenderSetup` / `RenderPipeline` structure and fields | Unchanged (including lazy `getTextures()` upload) | `.../rendertype/RenderType.java`, `RenderSetup.java` |
| `RenderPipeline.Builder#withUniform(name, UniformType)` | **Still present**; 26.1.x predates renderpearl, `UniformType` lives in `com.mojang.blaze3d.shaders` | `com.mojang.blaze3d.pipeline.RenderPipeline` |
| `RenderPipeline.Builder#withBlend(BlendFunction)` | Removed; use `withColorTargetState(new ColorTargetState(blend))` | same, `com.mojang.blaze3d.pipeline.ColorTargetState` |
| Builder default `depthStencilState` | `null` (≡ depth test disabled in `applyPipelineState`); set `DepthStencilState.DEFAULT` explicitly | same |
| `DefaultVertexFormat.NEW_ENTITY` | `ENTITY` (identical layout) | `com.mojang.blaze3d.vertex.DefaultVertexFormat` |
| `VertexFormatElement.Usage`, `getUsage()` / `usage()` | Removed; named element constants `UV0` / `UV1` / `UV2`, only `index()` / `type()` / `byteSize()` | `com.mojang.blaze3d.vertex.VertexFormatElement` |
| `RenderTypes.entityCutout(t)` (culling) | `entityCutout` is now **non-culling**; use `entityCutoutCull(t)` to cull | `.../rendertype/RenderTypes.java`, `RenderPipelines.ENTITY_CUTOUT*` |
| `RenderTypes.itemEntityTranslucentCull(t)` | Removed; `entityTranslucentCullItemTarget(t)` = `ENTITY_TRANSLUCENT_CULL` + `OutputTarget.ITEM_ENTITY_TARGET` | same |
| `Player#displayClientMessage(Component, boolean)` | Split into `sendSystemMessage(Component)` (chat) and `sendOverlayMessage(Component)` (action bar) | `net/minecraft/world/entity/player/Player.java` |

Bake-path notes: `CgcBaked` still uses `withUniform(..., UNIFORM_BUFFER)` (renderpearl arrives in 26.2);
the uv2 element is the registered singleton `VertexFormatElement.UV2`; `RenderSetup#getTextures()` must be called before opening a render pass.
