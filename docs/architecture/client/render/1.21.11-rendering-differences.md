# 1.21.10 → 1.21.11 渲染系统差异参考

> 用途同 [26.2 渲染系统差异参考](./26.2-rendering-differences.md)：只记录**原版 API 变更**与「去哪找源码」，
> 不记录本次移植改了什么（那见 [b1a 实施记录](./refactor/b1a-static-bake.md)「1.21.11」）。

---

## 一、总体

1.21.11 没有引入 26.2 的延迟提交框架，仍是即时提交。变化集中在**渲染状态的载体**：
`RenderStateShard` 被移除，`RenderType` 变成「`RenderPipeline` + `RenderSetup`」的数据对象，
着色器不再是可单独持有的程序（`ShaderInstance` / `ShaderProgram`），而是管线上的资源 id。

## 二、逐项 API 变更

| 旧 (1.21.10) | 新 (1.21.11) | 去哪找 |
|---|---|---|
| `net.minecraft.client.renderer.RenderType` | `net.minecraft.client.renderer.rendertype.RenderType` | `.../rendertype/RenderType.java` |
| `RenderStateShard`、`RenderType.CompositeRenderType` / `CompositeState` / `OutputStateShard` | 移除；状态进 `RenderSetup` | `.../rendertype/RenderSetup.java` |
| `CompositeRenderType#renderPipeline` | `RenderType#pipeline()` | 同上 |
| `RenderType#setupRenderState()` / `clearRenderState()` | 移除；`RenderType#draw(MeshData)` 自己组 pass | 同上 |
| `ShaderInstance` / `ShaderProgram` / `CompiledShaderProgram` | 移除；管线用 `withVertexShader(Identifier)` 直接指向资源 | `com.mojang.blaze3d.pipeline.RenderPipeline` |
| `RenderSystem.getShaderTexture(i)` / `getTextureMatrix()` / `getShaderLineWidth()` | 移除；贴图与纹理矩阵改从 `RenderSetup` 取 | `.../rendertype/RenderSetup.java` |
| `RenderPass#bindSampler(name, view)` | `RenderPass#bindTexture(name, view, sampler)` | `com.mojang.blaze3d.systems.RenderPass` |
| `writeTransform(mv, color, offset, texMat, lineWidth)` | 去掉线宽，4 参数 | `net.minecraft.client.renderer.DynamicUniforms` |
| `BufferBuilder.DrawState` | `MeshData.DrawState` | `com.mojang.blaze3d.vertex.MeshData` |
| `ResourceLocation` | `Identifier`（全局改名，不限渲染） | `net.minecraft.resources.Identifier` |
| `VertexConsumer` | 新增抽象方法 `setLineWidth(float)`、`setColor(int argb)` | `com.mojang.blaze3d.vertex.VertexConsumer` |

### RenderSetup 的结构

- `pipeline`、`textures`（`TextureBinding(location, sampler)`）、`useLightmap` / `useOverlay`、
  `outputTarget`、`layeringTransform`、`textureTransform`、`sortOnUpload`、`bufferSize`，全部包可见。
- `getTextures()` 把声明解析成 `Map<String, TextureAndSampler>`：`useOverlay` / `useLightmap` 会补
  `Sampler1` / `Sampler2`，其余经 `TextureManager#getTexture` 解析。
- **`getTextures()` 会按需加载纹理并立即上传**，不能在已打开的 render pass 内调用——
  `GlCommandEncoder` 会抛 `IllegalStateException: Close the existing render pass before performing additional commands`。

### vanilla `RenderType#draw(MeshData)` 的 pass 顺序

自定义绘制（持久 VBO 等）照这个顺序即可：

1. `layeringTransform` 的修饰器作用于 `RenderSystem.getModelViewStack()`；
2. `writeTransform(RenderSystem.getModelViewMatrix(), 白色 ColorModulator, 零 ModelOffset, textureTransform.getMatrix())`；
3. **先**取 `getTextures()` 与 `state.outputTarget.getRenderTarget()`，再处理 color/depth 覆盖；
4. 建 `RenderPass` → `setPipeline(state.pipeline)` → `bindDefaultUniforms` → `setUniform("DynamicTransforms", …)`；
5. 若 `RenderSystem.getScissorStateForRenderTypeDraws()` 启用则 `enableScissor`；
6. 绑顶点 / 索引（无独立索引缓冲时用 `RenderSystem.getSequentialBuffer(mode)`）→ 逐项 `bindTexture` → `drawIndexed`。

### 着色器与管线

- 自定义管线仍经 `RegisterRenderPipelinesEvent#registerPipeline` 注册；**同批注册内 location 必须唯一**，
  派生管线不要注册（`GlDevice` 按实例缓存编译结果）。
- 着色器 id 仍是资源路径形态：`<ns>:core/<name>` → `assets/<ns>/shaders/core/<name>.{vsh,fsh}`。
- 1.21.11 的 core 着色器是 `#version 330`，用 `#moj_import <minecraft:dynamictransforms.glsl>` /
  `<minecraft:projection.glsl>` 取 `ProjMat` / `ModelViewMat` / `ColorModulator` / `ModelOffset` / `TextureMat`。
- 模板测试仍由 NeoForge 的 `RenderPipeline#withStencilTest` 携带，`RenderSystem.applyPipelineModifiers` 仍在。

## 三、坑

- 在 render pass 内调用 `RenderSetup#getTextures()` → 崩溃（见上）。
- 派生管线若也走 `registerPipeline`，会撞 location 唯一性。
- **管线必须声明着色器用到的每个 UBO**：`GlProgram#setupUniforms` 只绑定管线声明过的块；
  着色器里有、管线里没有的块会打 `Found unknown and unsupported uniform …`（这条来自原版 `GlProgram`，不是 Iris），
  并且该块永远拿不到数据。注册即预编译的管线同样如此；**从 A 管线 `toBuilder()` 派生的 B 管线不会带上 A 额外加的声明**，
  每条用该着色器的管线都要自己声明。
- 烘焙网格是模型空间顶点：雾与法线仍要自己乘 `ModelViewMat` / 用 `IT(姿态)`，不能照抄 vanilla 的
  `fog_*_distance(Position)`（那套顶点已由提交阶段带到视图空间）。

# English

# 1.21.10 → 1.21.11 Rendering System Differences Reference

> Same purpose as the [26.2 reference](./26.2-rendering-differences.md): vanilla API changes only, plus where to look.
> CGC's own migration is described in [b1a](./refactor/b1a-static-bake.md)「1.21.11」.

## 1. Overview

1.21.11 keeps immediate submission; the change is in **how render state is carried**.
`RenderStateShard` is gone, `RenderType` is now `RenderPipeline` + `RenderSetup`, and shaders are resource ids on the
pipeline instead of standalone program objects.

## 2. API changes

| Old (1.21.10) | New (1.21.11) |
|---|---|
| `client.renderer.RenderType` | `client.renderer.rendertype.RenderType` |
| `RenderStateShard`, `CompositeRenderType` / `CompositeState` / `OutputStateShard` | removed; state lives in `RenderSetup` |
| `setupRenderState()` / `clearRenderState()` | removed; `RenderType#draw(MeshData)` builds its own pass |
| `ShaderInstance` / `ShaderProgram` / `CompiledShaderProgram` | removed; `withVertexShader(Identifier)` on the pipeline |
| `RenderSystem.getShaderTexture/getTextureMatrix/getShaderLineWidth` | removed; read from `RenderSetup` |
| `RenderPass#bindSampler(name, view)` | `bindTexture(name, view, sampler)` |
| `writeTransform(..., lineWidth)` | four parameters |
| `BufferBuilder.DrawState` | `MeshData.DrawState` |
| `ResourceLocation` | `Identifier` |
| `VertexConsumer` | new abstract `setLineWidth(float)`, `setColor(int)` |

Key facts:

- `RenderSetup` fields are package-private; `getTextures()` resolves and **uploads** textures — never call it inside an open
  render pass (`IllegalStateException: Close the existing render pass before performing additional commands`).
- Every UBO the shader uses must be declared by the pipeline (`withUniform`); otherwise vanilla `GlProgram` logs
  `Found unknown and unsupported uniform …` and never binds the block — including pipelines that are precompiled on registration.
  A pipeline built via `toBuilder()` from another pipeline does **not** inherit declarations that were only added to that other pipeline.
- Vanilla pass order: layering modifier → `writeTransform` → textures/output target → build `RenderPass` →
  pipeline/uniforms/scissor/vertex/index/bindTexture/drawIndexed.
- Custom pipelines still register via `RegisterRenderPipelinesEvent`; locations must be unique within a batch, so do not
  register derived pipelines.
- Shader ids remain `<ns>:core/<name>`; 1.21.11 core shaders are `#version 330` with `dynamictransforms.glsl` /
  `projection.glsl` includes.
- Model-space baked meshes must still transform normals and fog themselves; vanilla entity shaders sample fog from the
  raw submitted `Position`.
