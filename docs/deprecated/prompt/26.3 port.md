## 最初那个错误的原因

26.3 把渲染后端从 `blaze3d` 拆到了新的 `com.mojang.renderpearl` 包树，`RenderPipeline` / `ColorTargetState` / `DepthStencilState` / `PrimitiveTopology` 全部换了包。修掉之后暴露出 75 个错误，分属十来个子系统。

## 处理的主要变更

**包迁移（机械）**：`blaze3d.pipeline.*` → `renderpearl.api.pipeline.*`，`blaze3d.PrimitiveTopology` → `renderpearl.api.pipeline`，`blaze3d.opengl.GlStateManager` → `renderpearl.backend.opengl`，`blaze3d.platform.CompareOp` → `renderpearl.api.pipeline`。`RenderTarget` / `vertex.*` / `platform.*` 原地不动。

**`PoseStack.mulPose(Quaternionfc)` → `rotate(Quaternionfc)`**（约 45 处）。对的实现体逐字相同，只是改了名。

**`ItemInHandRenderer` 被删除**（这是规则里说的"平台删除功能"情形，需要你确认）：26.3 拆成玩家持有的 `FirstPersonHandsAndItems`（`tick`/`mainHandHeight` 等字段全在这里）+ `FirstPersonHandsAndItemsRenderer`。原来的 `ItemInHandRendererMixin` 拆成了两个 mixin，`KeepingItemRenderer.cgc$getRenderer()` 改从 `LocalPlayer.firstPersonHandsAndItems()` 取。为保住"永远返回非空"的原约定、不改动 9 个调用点，加了个 `EMPTY` 空实现兜底。

**模板测试的载体变了**：从 `RenderPipeline` 的独立字段挪进了 `DepthStencilState` 的第 5 个分量。因此 `PipelineModifier.NO_DEPTH_WRITE` 必须显式带上 `stencilTest`，`RenderSystem.applyPipelineModifiers` 消失后注入点改挂到 `PipelineModifierStack.apply`（新增了 `RenderSystemAccessor` 取私有修饰器栈）。

## 需要你判断的语义取舍

1. **`CommandSourceStack` 不再接受 `textName`/`displayName`** —— 名字只能由 entity 推导（`NamesProvider`）。4 个 core 事件 + 19 个 neoforge 包装事件按"有 entity 就用 entity 构造器"统一处理。副作用：`ProjectileHitBlockEvent` 的名字会从"方块名"变成"射物名"。已在 `IEvent.createCommandSourceStack` 的 javadoc 里写明。
2. **`entityTranslucentCullItemTarget` 连同 `OutputTarget.ITEM_ENTITY_TARGET` 整体被删除**，映射到 `entityTranslucentCull`（原版自己也是这么改的）。
3. **`_AttachmentModelRender` 去掉了 `target.useStencil` 前置判断** —— 该字段已不存在，只保留 `getDepthTexture() != null`。
4. **`RenderSetup` 变不可变且构造器私有**，`OutputTarget` 被 `OitPipelineSet` 取代、多出 `outlineTextureName`/`forceSolidModelPhase`。我在 `neoforge-compat` 的 AT 里放开了构造器与全部字段（26.2 那批 `outputTarget` 条目已删除，否则会因字段不存在报错）。
