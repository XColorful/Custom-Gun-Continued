# 测试数据计算报告（CGC 1.20.1 · b1-b-3：光照变化下的重烘焙）

**数据**：本目录 4 次独立启动（n=4），每次含 Afterburner 与 F12 两段，时间不重叠。
- `cgc1 (N).txt`：Afterburner 7 步 = 空手（夜晚静止）/ ak47 移动 / ak47+光影 静止 / ak47+光影 移动 / 满配 移动 / 满配+光影 静止 / 满配+光影 移动
- `cgc1-builtin (N).txt`：F12 4 段 = ak47 移动 / ak47+光影 移动 / 满配 移动 / 满配+光影 移动

**场景**：夜晚、脚下火把、按 W 走 8 格后由命令方块传送回起点、再走 16 格；移动时每跨一格方块光 −1，约每秒 2.6–2.9 次光照变化。
**口径**：帧时间 = 1000 / FPS；均值 ± 1 样本标准差。`Static bake` 的探针平均值是**命中帧内所有烘焙之和**，不是单次烘焙；命中帧比例 × FPS = 重建帧/秒。手动起停误差 ≤0.5–1 s。
**复现**：`python analyze.py`。

## 1. 帧时间（Afterburner）

|步骤|AF 帧时间|1% low|
|---|---:|---:|
|空手（夜晚静止）|0.822 ± 0.008 ms（1216.5 FPS）|510.4|
|ak47 移动|1.220 ± 0.031（819.7）|329.6|
|ak47+光影 静止|6.536 ± 0.052（153.0）|135.2|
|ak47+光影 移动|6.355 ± 0.017（157.3）|132.1|
|满配 移动|1.411 ± 0.030（708.9）|331.5|
|满配+光影 静止|7.056 ± 0.025（141.7）|118.5|
|满配+光影 移动|**6.912 ± 0.022**（144.7）|**55.2**|

- 无光影没有静止对照，移动段的 AF 增量（0.398 / 0.589 ms）混有走动本身（世界侧）的成本，**枪械成本以第 2 节的 CGC 探针为准**。
- 光影下移动比静止还快 0.14–0.18 ms，方向与预期相反，见第 5 节；两者的 10 s 记录在同一进程内。
- 满配+光影移动的 1% low 从 118.5 掉到 **55.2**（约 18 ms 的帧），是本批唯一明显的尖峰信号。

## 2. 重建的次数与成本（F12，移动段）

|项|ak47 移动|ak47+光影|满配 移动|满配+光影|
|---|---:|---:|---:|---:|
|CGC|0.199 ± 0.005|0.360 ± 0.026|0.480 ± 0.011|1.438 ± 0.143|
|`Bake rebuilds`（次/帧）|0.020|0.130|0.060|0.340|
|重建帧比例|0.30%|1.80%|0.40%|2.00%|
|重建次数/秒|**2.6**|**2.8**|**2.8**|**2.9**|
|单次重建（该帧合计）|**0.595 ± 0.009 ms**|**2.736 ± 0.229 ms**|**1.383 ± 0.018 ms**|**9.098 ± 0.824 ms**|
|每次重建的块数|≈6.7|≈7.3|≈15|≈17|
|p99 帧时间|2.260 ms|9.967 ms|2.550 ms|**15.384 ms**|
|最大帧时间|11.555 ms|15.533 ms|4.821 ms|**27.191 ms**|

- **重建次数只跟走路有关**：约 2.6–2.9 次/秒，三种配置一致；光影下比例变大（1.8%–2.0%）只是因为帧率低（157 / 145 FPS），次数没变。
- 一次光照变化会重烘整枪的块：ak47 约 7 块、满配约 15–17 块（含瞄具模板的网格）。之后连续走后光强降到 0 就不再变化。
- **单次重建的成本约等于重构前的单帧成本**：ak47 0.595 ms（B1-b 前 0.54–0.61）、满配 1.383 ms（B1-b 前 1.99–2.20，重建不含 delegate / 瞄具模板，所以更低）。
- **光影下单次重建贵 4–6 倍**（2.74 / 9.10 ms）：顶点格式被光影扩展、上传时 GPU 已经排满。这是本批最值得注意的一项。

## 3. 对帧时间的影响

|场景|命中帧占比|单次|折合每帧平均|
|---|---:|---:|---:|
|ak47|0.30%|0.595 ms|1.8 µs（0.16%）|
|ak47+光影|1.80%|2.736 ms|49 µs（0.77%）|
|满配|0.40%|1.383 ms|5.5 µs（0.39%）|
|满配+光影|2.00%|9.098 ms|**182 µs（2.6%）**|

- **平均帧时间几乎不受影响**：移动段的 CGC 0.199 / 0.480 与静止（`26.35.11.1-5` 的 0.202 / 0.540）持平；光照重建只占 0.4%–2.6%。
- **尖峰按命中率决定落在哪个分位**：无光影命中率 0.3%–0.4%，低于 1% 分位，所以只体现在 0.1% low（ak47 移动的 0.1% low 在 30–194 FPS 之间大幅波动）；光影下命中率 1.8%–2.0%，高于 1% 分位，**1% low 直接被重建帧决定**（满配 118.5 → 55.2，p99 帧时间 8.5 → 15.4 ms，最大 27 ms）。
- 无光影的 1% low（329.6 / 331.5）比 `b1-b-1` 的静止（464 / 415）低，但本批没有无光影静止对照，不能全部归因于光照重建（走动本身也有成本，见第 1 节）。

## 4. 结论（对应 V2）

1. **光照变化不会让优化全没**：平均 CGC 不变；只有跨过亮度边界的那一帧退回重构前的单帧成本，每秒 2.6–2.9 次、占比 0.3%–2%。
2. **观感**：夜间连续走动会有周期性小卡顿——无光影落在 0.1% low，满配+光影落在 1% low（约 18–27 ms 的帧）。光影下重建贵 4.6–6.6 倍是主因。
3. **不建议做整套光照解耦**：收益上限只有平均 182 µs/帧（满配+光影），而 uniform 方案在光影下不可行（Iris program 读 `vaUV2`），等于放弃光影兼容。
4. **若要消除尖峰，优先改重建路径**：单次重建的主要成本是「新建 `VertexBuffer` + 全量上传 + 重算顶点」。可选：复用 `VertexBuffer` 原地重传、光照变化时只重写 `uv2`（无变换）、提高每块网格的光照条目上限（走回头路时命中缓存）。这些同时降低所有重建成本，比光照解耦更划算。

## 5. 说明与异常

- 光影下「移动」比「静止」快 0.14–0.18 ms（满配 7.056 → 6.912）：两次记录在同一进程内，最可能是一次性预热 / 视角差异，无法从本批数据分离。它不影响第 2 节的结论——重建次数与单次成本由 F12 直接测得。
- 静止记录的采样点就是火把位置：火把有火焰/烟粒子，光影包在光源附近也可能更贵，这可以解释静止反而更慢。若要做这个对照，把火把换成 `minecraft:light` 方块（不可见、无粒子，`/setblock ~ ~ ~ light[level=15]`）或萤石再测一次即可。
- 「静止」记录在火把位置（方块光 14），「移动」离开火把、光照逐格下降，到 14 格外为 0；因此一半的路程之后不再触发重建，2.6–2.9 次/秒比「每格一次」低。
- 命令方块传送回起点会让光照瞬间从 0 跳回 14，也触发一次重建；每段约 1 次。
- 手动起停（左手 W + 右手 F12/Afterburner 热键）误差 ≤0.5–1 s，只影响 AF 的平均值，不影响 F12 的计数类指标。
- 光影下 `CGC GPU busy` 不可信，本批未用于归因。
