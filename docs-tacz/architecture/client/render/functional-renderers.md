# 枪械附加渲染模块

> 枪械最终呈现的结果不只是基础模型几何，还叠加了一系列按需渲染的模块

枪械模型在 `BedrockGunModel` 构造时注册了大量「功能性渲染器」，它们决定某些节点画什么、是否可见、以什么方式画。此外还有激光束等独立绘制路径。这些模块共享同一个机制：`FunctionalBedrockPart` 让节点的渲染逻辑在渲染时被替换，替换函数返回 `null` 时回退到默认几何。

## 机制：可替换渲染与延迟绘制

`FunctionalBedrockPart` 持有一个 `Function<BedrockPart, IFunctionalRenderer>`。渲染时调用它：

- 返回非空渲染器：该节点的默认几何被完全跳过，改由渲染器绘制。
- 返回 `null`：回退到默认几何。

一个关键细节是 `visible == false` 不会抑制功能性渲染器，它只关闭默认几何分支。因此很多「可见性控制」模块的写法是：在函数里改 `visible` 然后返回 `null`，让默认几何按新可见性绘制。

多数需要「在节点位置画额外东西」的模块（枪口火焰、抛壳、配件、手臂、文字）采用**延迟绘制**：在遍历到该节点时缓存当时的 `PoseStack` 矩阵，把实际绘制注册到模型的 `delegateRenderers` 列表，等几何批次刷出后再统一执行。这样额外内容能画在枪体之上。

## 枪口火焰 MuzzleFlashRender

在枪口节点位置渲染枪口火焰。开火时记录时间戳并生成随机旋转，随后在约 50ms 的窗口内画一个发光的小模型：一层半透明底色加一层 `energySwirl` 高光，缩放来自 display 的 `muzzle_flash` 配置。若枪口安装了消音器则跳过火焰。它用静态 `isSelf` 标志只对本地玩家的枪生效，阴影通道下也不渲染。

## 抛壳 ShellRender

渲染抛出的弹壳动画。开火时按 `ShellEjection` 配置的初速度/随机速度/加速度/角速度入队一枚弹壳，随后每帧在抛壳口位置用匀加速位移和角速度旋转绘制弹壳模型，超时后出队。队列上限 128。弹壳的模型和贴图来自弹药 display 的 `shell` 字段。

## 激光束 BeamRenderer

渲染枪械或激光配件的激光束。它不是功能性渲染器，而是由 `BedrockGunModel.render` 和 `BedrockAttachmentModel.render` 主动调用的静态绘制：沿着 `laser_beam` 节点路径画一组交叉的四边形，用加性混合与满亮度，颜色来自 `LaserConfig`。激光束只在第一人称或第三人称右手渲染，避免其他场景出现不必要的光柱。

## 配件渲染 AttachmentRender

在 `_pos` 节点位置渲染已安装的配件模型。渲染时解析配件索引，应用 LOD（远距离切换低模），用 `entityCutout` 绘制配件模型。瞄具配件最特殊——它在渲染枪体之前先行绘制，往模板缓冲区写入镜片形状，随后枪体在模板测试下被镜片区域遮挡，实现「透过瞄具看世界」的效果。

## 第一人称手臂 LeftHandRender / RightHandRender

在 `lefthand_pos` / `righthand_pos` 节点处渲染玩家的第一人称手臂。手臂继承枪械的变换，额外做 180° 翻转，通过 `RenderHelper` 调用玩家渲染器把手臂画到该节点位置。手臂在改装界面打开时会被关闭，因为此时镜头聚焦在配件上。

## 文字 TextShowRender

在模型节点上绘制文字。display 的 `text_show` 字段定义节点名与文字内容（经占位符系统解析），渲染时按对齐方式计算偏移并调用字体绘制，支持自发光亮度。用于枪械/配件上的浮空文字（如弹药计数）。

## 子弹与弹匣可见性

`BedrockGunModel` 注册的多数功能性渲染器其实是「可见性控制」：它们根据枪械当前状态设置节点的 `visible`，然后返回 `null` 走默认几何。包括：

- 枪管内子弹、弹匣内子弹、弹链：按是否有子弹显示。
- 瞄具导轨 / 提把 / 折叠瞄具 / 机械瞄具：按是否安装瞄具显示。
- 扩容弹匣一/二/三级与标准弹匣：按当前扩容等级显示。
- 额外弹匣：换弹动画中第二个弹匣，只有动画中有关键帧时才显示。
- 护木默认/战术形态：按是否安装激光/握把切换。
- 配件转接口：按当前安装配件需要的转接节点显示子节点。

这些模块本身不产生新几何，但通过控制几何的可见性，实现了枪械随配件组合和状态变化的外观切换。
