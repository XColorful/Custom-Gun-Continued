# 测试数据计算报告（CGC 1.20.1 · b1-a-7：换弹与脏节点）

**数据**：本目录 8 次独立启动。`1–4` 是脏子树探针修复之前的构建，`5–8` 是修复之后；本报告只用 **5–8（n=4）**。
每组 = 先 Afterburner 记录 4 段静止帧时间（空手 / ak47 / m4a1 裸配 / m4a1 满配），再在同一场景各跑一段 DebugKey 自动换弹（0/3/6 秒各触发一次，10 秒后自动停止），共 3 段 F12 数据。
**口径**：帧时间 = 1000 / FPS；均值 ± 1 样本标准差。AF 与 F12 分开运行，F12 帧时间含探针开销，只用于同口径比较。换弹段 9–10 秒为空闲，用作段内对照。
**复现**：`python analyze.py`。

## 3. 脏节点与脏子树

|场景|`Dirty nodes` 均值|峰值|p99|`Dirty subtree nodes` 均值|峰值|p99|
|---|---:|---:|---:|---:|---:|---:|
|ak47 换弹|3.29|**14**|6|63.9|**198**|188|
|m4a1 裸配 换弹|2.54|**12**|6|47.3|**154**|136|
|m4a1 满配 换弹|2.57|**9**|6|47.9|**156**|140|

占本帧遍历节点数的比例：

|场景|遍历节点数|`Dirty node share`|`Dirty subtree share`|p99 覆盖|
|---|---:|---:|---:|---:|
|ak47 换弹|352|0.9%|**18.1%**|**53%**|
|m4a1 裸配 换弹|613|0.4%|**7.7%**|**22%**|
|m4a1 满配 换弹|1578|0.2%|**3.0%**|**8.8%**|

- 静止时只有根节点的 bob 在变（`Dirty nodes = 1`、脏子树 = 0，根不计入）；换弹时动画骨骼带着约 150–200 个节点一起动。
- **脏节点数（峰值 9–14）远小于脏子树（峰值 154–198）**：动画只驱动少数骨骼，但它们各自的子树在模型空间里都要重烘焙。只看 `Dirty nodes` 会把换弹的成本低估一个数量级——这正是先补脏子树口径的原因。
- ak47 的覆盖比例最高（遍历节点少、动画子树差不多大）：换弹时约 **一半**的遍历无法跳过；m4a1 满配只有 **9%–10%**。
- 约 20%–33% 的帧脏子树为 0（纯空闲帧或只有根在动），说明换弹动画是分段的，**均值会被稀释，B1-b 评估用 p99 / max**。
- `Distinct nodes` 换弹时从 361 降到 352（ak47）：换弹动画或 functional 节点的替换渲染让 9 个节点不再参与遍历，分母随可见性变化，比例只作量级参考。

**这条口径的边界**：脏子树的单位是**节点**，而重烘焙的成本按**顶点（cube）**计。如果动画骨骼上 cube 密度高（弹匣、枪机通常是有实体的），实际残留会高于节点占比；如果动画骨骼基本是空变换节点，实际残留会更低。要给出成本口径的结论，需要一个 cube 加权的脏计数（已登记到 [TODO](../../TODO.md)）。

**开火与检视不单独作为基准**：开火只驱动栓与整枪（整枪走根矩阵，不计入脏子树），检视是换弹的慢放版本且驱动通道更少——两者的脏集都不会超过换弹，换弹即可作为动态场景的上界。

## 4. 重构收益会被换弹吃掉吗

不会，但要把「换弹峰值」和「常规帧」分开看。

|量|ak47|m4a1 裸配|m4a1 满配|
|---|---:|---:|---:|
|p99 脏子树覆盖|53%|22%|**8.8%**|
|可跳过的遍历（p99）|47%|78%|**91%**|
|换弹峰值遍历残留（推算）|≈0.18 ms|≈0.12 ms|**≈0.07 ms**|
|该枪总遍历（换弹段）|0.338 ms|0.548 ms|0.824 ms|

- B1-b 的主目标是满配第一人称：换弹峰值下仍有 **91% 的遍历可以跳过**，残留约 0.07 ms；相对 CGC 1.994 ms 只有 3.5%。目标区间 0.45–0.60 ms 不需要为换弹放宽。
- ak47 是相对最坏的一把（p99 只剩 47% 可跳过），但它的总遍历只有 0.338 ms，且不是 B1-b 的目标场景。
- 「脏节点比脏子树差一个数量级」说明的是**旧口径会低估成本**，而不是收益消失：脏节点是动画驱动的骨骼数，脏子树才是需要重写顶点的范围。
- 换弹只占少数帧：20%–33% 的帧完全干净；整段均值覆盖只有 18.1% / 7.7% / 3.0%。
- **剩下的风险在 cube 密度**：若弹匣/枪机上的 cube 占比接近其节点占比，上式成立；若更高，残留会按比例上升（最高不超过总遍历）。

## 5. 对模型与动画的制作准则

本批数据把成本模型落到「脏子树」上，由此可以直接约束美术制作。完整清单见 [方案 B 的美术制作约束](../../refactor/scheme-b-baked-mesh.md#美术制作约束)，三条核心：

1. **动画骨骼放在层级低处、子树要小**：静态装饰不要挂在动画骨骼下面，重烘焙按整棵子树走。
2. **动画骨骼上少放 cube**：成本按顶点计，不可见面剔除这类制作期优化会直接乘在每次重烘焙上。
3. **整枪的呼吸/晃动放在根节点**：根变换由绘制矩阵承担、不产生重烘焙；放在子骨骼上会让整个模型每帧变脏。

换弹的实测覆盖（p99 53% / 22% / 8.8%）要这样读：两把枪的脏子树**绝对量差不多**（154–198 个节点），差别主要来自模型总规模——ak47 只有 352 个节点，同样一组动画骨骼就占了过半；满配 m4a1 有 1578 个节点，同一组骨骼只占不到 10%。因此降低占比有两个手段：**缩小动画骨骼自己的子树**（层级与归属），以及**让静态部分不进这棵子树**。前者由模型层级与 cube 归属决定，后者由动画驱动哪些骨骼决定，都可以在制作期控制。

## 6. 异常与说明

- 本批静止帧时间比 `b1-a-5` 高 2%–4%，两次都是同一探针集，属进程噪声；跨批比较按 ±4% 处理。
- 三段换弹的 `Dirty subtree nodes` 分别为 63.9 / 47.3 / 47.9（均值），裸配与满配几乎相同——动画驱动的子树（弹匣、枪机）在两种配置下是同一组骨骼，满配多出来的配件模型各自是独立 `ModelObject`，根变换不计入本模型的脏子树。
- 满配换弹的 `Scope render` 0.726 与静止 0.713 基本一致：换弹不开镜，瞄具模板成本不变。
- `MAG_ADDITIONAL` 的整模型退回在换弹时确实会命中（附加弹匣直接发射几何）。第一人称现在本来就是即时路径，本批没有影响；B1-b 烘焙后如果不做单节点退回，换弹帧会整帧退回——已登记到 [TODO](../../TODO.md) 的阶段 2。
- 采集全程关闭 F3；开光影时 `CGC GPU busy` 不可信，本批未开光影。
